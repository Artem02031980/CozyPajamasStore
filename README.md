# Магазин уютных пижам

Учебный проект: вёрстка сайта интернет-магазина пижам по готовому дизайн-макету.

**Стек:** чистый HTML, CSS и JavaScript. Без сборщиков, без фреймворков, без PHP.
Корзина и оформление заказа работают только на JavaScript, с сохранением в `localStorage`.
После покупки открывается страница `thanks-cart.html` с благодарностью за покупку.

## Как открыть проект

Только через локальный сервер — двойной клик по `index.html` не сработает:
браузеры блокируют ES-модули на `file://` из-за политики CORS, и скрипты
не запустятся.

```powershell
cd C:\Sites\CozyPajamasStore
python -m http.server 8000     # затем http://localhost:8000
```

Подойдёт и расширение Live Server в VS Code: правый клик по `index.html` →
«Open with Live Server».

## Верстка

Проект верстается по методологии **БЭМ**: имена классов — блоки, элементы (`__`)
и модификаторы (`--`). Например: `.goods-women`, `.product-card__title`,
`.button--accent`. Слои стилей повторяют уровни БЭМ: переиспользуемые блоки
лежат в `blocks/`, привязка блока к месту на странице — в `sections/`.

| Файл | Что это |
|---|---|
| `index.html` | главная: шапка, hero, секции каталога, форма, подвал |
| `thanks-cart.html` | «Спасибо за покупку!» после оформления заказа |
| `thanks-feedback.html` | «Спасибо!» после отправки формы «Задайте вопрос» |
| `product-pages/*.html` | страница одного товара; своя для каждой пижамы |

**Каталог живёт в данных, а не в разметке.** Карточки товаров рисует
`render.js` из массива `PRODUCTS` в `data.js`. В `index.html` остаются
только пустые сетки — `<ul class="goods-new__grid">` и такие же для
остальных секций. Чтобы добавить товар, правят `data.js`, а не разметку.

Цена в `data.js` хранится **числом** (`9399`), а не строкой: её нужно
складывать в корзине и сортировать. Печатает её `formatPrice` из
`utils.js` — он расставляет неразрывные пробелы и знак рубля, поэтому
в вёрстке цена выглядит как «9 399 ₽».

### Фильтры и сортировка

Фильтры работают в женской и мужской коллекциях. Группы: тип изделия, возраст,
палитра цветов, цена. Внутри группы условия складываются по «или» (Пижама ИЛИ
Халатик), между группами — по «и» (тип И цвет И цена). Выбор снимается
повторным нажатием, кнопка «Сбросить фильтры» очищает всё сразу.

Логику отбора считает `filters-query.js` — чистые функции без DOM, поэтому
её проверяет `node checks/filters.mjs` без браузера. `filters.js` занимается
разметкой, событиями и состоянием.

**Значения фильтров берутся из самой разметки**, а не из отдельной таблицы:
в `data.js` у товара есть теги `types`, `ages`, `colors`, записанные ровно
теми же строками, что подписи чипсов и `aria-label` кружков в `index.html`.
Добавили чипс — он заработает, если у товаров есть такой тег; тег без чипса
не показывается. Проверка `checks/filters.mjs` следит, чтобы теги и чипсы
не разъехались.

**У каждой коллекции свой словарь фильтров.** Возраст в женской — «Для юных
дам / Для девушек / Для мудрого возраста», в мужской — «Для молодых людей /
Для мужчин / Для мудрого возраста». Теги товаров должны совпадать с чипсами
**своей** секции, иначе фильтр молча не сработает: чипс на странице есть,
но не в этой форме. Проверка сравнивает теги с чипсами по каждой секции
отдельно.

Обводка фокуса у сортировки и у кружков палитры покрашена в акцент секции:
`--color-pink` (#cd74a2) в женской, `--color-blue` (#93b3d6) в мужской.
Цвет задан свойством `--filters-focus` в файлах секций, а сама обводка
остаётся — по ней ориентируются те, кто ходит по странице с клавиатуры.

**У кружков палитры обводка показывает оба состояния, и они различаются
толщиной:** фокус — 5px, выбранный цвет — 3px, в покое обводки нет.
Рамку для выбора использовать нельзя: у `.filters__color` задан шорткат
`border: 1px solid var(--color-transparent)`, и его специфичность (0-2-0) выше,
чем у `.filters__color.is-active { border-color }` (0-1-0), — правило молча
не срабатывало, и выбранный цвет на цветных кружках выглядел как невыбранный.
Обводка же не спорит ни с рамкой белого кружка (она означает только одно:
это белый цвет), ни с состоянием фокуса.

Теги размечены у 18 товаров секций `women` и `men`. У «Новой коллекции»
и «Других товаров» тегов нет: фильтров в этих секциях не бывает, и выдумывать
им типы незачем.

Сортировка — выпадающий список над сеткой: порядок каталога, сначала дешёвые,
сначала дорогие, по названию. Ключ сортировки совпадает со значением
`<option>`, поэтому новый вариант добавляется одной строкой в `filters-query.js`
и одним пунктом в разметке. Диапазоны цены разбираются из подписи чипса
(`parsePriceLabel`): «до 4999₽» — верхняя граница, «5000 - 9999₽» — обе.

Если по условиям ничего не нашлось, вместо сетки показывается сообщение,
а пагинация скрывается.

**Женская и мужская коллекции показываются постранично** (`filters.js`).Сколько карточек на странице, зависит от ширины экрана и совпадает
с числом колонок в сетке:

| Ширина | Колонок | Карточек на странице | Страниц (по 9 товаров) |
|---|---|---|---|
| до 768px | 1 | 5 | 2 |
| 768–1279px | 2 | 6 | 2 |
| с 1280px | 3 | 9 | 1 |

Кнопки страниц строит `filters.js` — их число зависит от количества
товаров, поэтому в разметке лежит только пустой `<ul class="pagination__list">`.
При изменении ширины окна страница пересчитывается: иначе на новом числе
колонок в последнем ряду оставались бы дыры.

Клик по кнопке страницы возвращает экран к началу списка товаров — так же,
как при переходе по ссылке пагинации на сайте-образце (jackmenn.ru):
новая страница открывается сверху, и видно первую строку карточек.
Отступ липкой шапки задаёт `scroll-margin-top` у сеток в `layout.css`.

Секции «Новая коллекция» и «Другие товары» показываются целиком,
без пагинации.

### Корзина и оформление заказа

`cart.js` хранит состав корзины, считает суммы и знает правила услуги
«ПРИНТ»; `render-cart.js` собирает разметку; `cart-ui.js` связывает их
со страницей. В хранилище лежат только ссылки на товары — `{id, qty, size}`.
Название, цену и фото даёт `data.js`, поэтому правка цены в каталоге сразу
видна в корзине. Заказ (в отличие от корзины) хранит снимок названий и цен:
это документ, и он не должен меняться задним числом.

Внутри группы кнопок «В корзину» на карточке размер не выбирается — товар
добавляется без размера. Размер появится на странице товара (шаг 5);
тогда один товар в разных размерах станет двумя позициями — `variantKey`
из `utils.js` уже это поддерживает.

Услуга «ПРИНТ» бесплатна, когда сумма товаров (без неё самой) дотянула
до порога. Цена и порог заданы в разметке кнопки — `data-print-price`
и `data-print-free-from`. В итогах при этом печатается «бесплатно», а не
«0 ₽», и итог равен сумме товаров; пока порога не хватает, показывается,
сколько осталось добрать.

Окно корзины — общий блок `modal`: открытие по `data-modal-open`, закрытие
по ESC, по затемнению и по крестику, ловушка фокуса, возврат фокуса на
кнопку открытия и блокировка прокрутки (`modal.js`).

Форма оформления живёт внутри окна корзины и создаётся тем же
`render-cart.js`. Проверяет и отправляет её `checkout.js`: имя, телефон
(не меньше 10 цифр) и необязательная почта. Адрес перехода после заказа —
в атрибуте `data-checkout-redirect` у формы, поэтому страница товара сможет
вести на свою страницу благодарности.

`thanks-cart.html` читает заказ из `localStorage` (`thanks.js`) и показывает
номер, дату, состав и итог. Если заказа нет — блок «Заказа пока нет» вместо
пустого экрана.

### Форма обратной связи

Форма «Задайте вопрос» — последняя секция главной (`#feedback`). Сервера
у проекта нет, поэтому `feedback.js` делает то, что на статичном сайте
возможно: проверяет текст, кладёт его в `localStorage`
(`cozy-pajamas:message`) и ведёт на `thanks-feedback.html`.

Проверка вопроса — от 10 до 1000 символов. Нижняя граница отсекает
сообщение, на которое невозможно ответить, верхняя совпадает с `maxlength`
у поля: если границы разойдутся, браузер обрежет текст, который модуль
считает нормальным. У формы стоит `novalidate` — ошибку показывает модуль
подписью под полем, а не системный пузырь браузера, который не перевести
и не оформить. Подпись вынута из потока (`position: absolute`): на 768px
и выше поле и кнопка стоят в одну строку, и третий элемент в ней сломал бы
макет.

Без скрипта форма тоже работает: у неё есть `action` и `method`, браузер
уходит на страницу благодарности обычной отправкой, а та честно говорит,
что сообщение не сохранилось, и зовёт обратно к форме. Пустое состояние
на `thanks-feedback.html` — не заглушка, а рабочий сценарий.

**Поле вопроса всегда начинается пустым.** Браузер сам восстанавливает
значения форм, когда человек возвращается на страницу по кнопке «назад»,
и в поле оказывался прошлый вопрос — рядом с подписью «Напишите вопрос —
поле пустое» это выглядело поломкой. Поэтому у формы и у поля стоит
`autocomplete="off"`, а `feedback.js` очищает поле при запуске и на событие
`pageshow`: возврат из кеша страницы (bfcache) события `load` не вызывает,
модуль при этом уже выполнен.

Кнопки возврата на обеих страницах благодарности оформлены как «Вернуться
к покупкам» в пустой корзине (`.cart__continue`): рамка `1px` розовая,
текст розовый, при наведении и рамка, и текст синие, скругление — токен
`--radius-sm` (8px), а не «пилюля» базовой кнопки. Модификатор
`button--outline` в разметке этих кнопок не ставится: у него свой бежевый
цвет рамки, и он спорил бы с оформлением страницы.

`thanks.js` обслуживает обе страницы благодарности: заказ показывает
`initThanks`, вопрос — `initThanksFeedback`. Текст вопроса печатается
через `textContent`, а не `innerHTML`: это то, что написал человек,
и разметкой оно быть не должно. Переносы строк сохраняет
`white-space: pre-line`.

### Страница товара

Свёрстана одна страница — `product-pages/klubnichnye-polya.html`, товар
«Клубничные поля» из женской коллекции. Макеты: `figma/768-1280-.jpg`
(от 768px) и `figma/320-768.jpg` (до 767px). Pixel Perfect не требуется,
но порядок блоков и пропорции взяты из макетов.

**Разметка статична: товар, фото и характеристики стоят в HTML, а не
рисуются скриптом.** Страница должна читаться и без JavaScript, поэтому
`product.js` добавляет только поведение: листание галереи, выбор размера
и галочку услуги. Обратная сторона — данные дублируются в `data.js`
и в разметке, и расхождение ловит `checks/product.mjs`: он сверяет
название, цену, описание, характеристики и размеры фото с файлом.

Данные для страницы лежат отдельными полями товара в `data.js` — `sizes`,
`description`, `details`. Поля необязательные: у остальных 140 товаров
их нет, и страница должна работать без них.

Что из макета и почему сделано иначе:

| В макете | В проекте | Почему |
|---|---|---|
| Стрелки листания и точки | Только точки до 767px, стрелки — на всех ширинах | Кадр один: точек хватает, а стрелки выключены и стоят задел под вторые ракурсы |
| Кнопки в строку | В столбик на всю ширину колонки | Две кнопки занимают 462px, колонка информации — 312px: в строку на 768px появлялась горизонтальная прокрутка страницы |
| Карточка на всю ширину | `max-width: 720px` | В макете карточка занимает половину экрана; при полной ширине стрелкам листания негде встать, они ложились на карточку |
| Галочка «Добавить услугу нанесения принта» | Работает: кладёт в корзину услугу `print` | Без этого галочка выглядела бы декоративной |

Кнопки «Выбрать из каталога» и «Добавить свой макет» пока сообщают о себе
в консоль: сам выбор макета — шаг 6.

**Файлы из макета.** `bg.png` → `assets/images/product-page/bg.png`
(фон включается с 768px; на мобильном он выключен — за карточкой во всю
ширину его не видно, а весит файл 1.4 МБ). `icon-circle.svg` →

`icon-catalog.svg` → `assets/images/icons/icon-catalog.svg` (иконка на

по масштабу.

Товарные страницы лежат на уровень глубже корня, поэтому пути к общим файлам
идут через `../` — например `../assets/css/style.css` и `../index.html`.
У `index.html` и страниц благодарности пути обычные, они в корне.

## Скрипты на разных страницах

`script.js` подключается на всех страницах, но каждая страница запускает
только свои модули. Признак страницы — атрибут `data-page` на `<body>`:

| `data-page` | Что запускается |
|---|---|
| `home` | отрисовка секций, фильтры, корзина, оформление заказа, форма вопроса |
| `product` | галерея, размеры, услуга «ПРИНТ», корзина |
| `thanks-cart` | показ состава заказа из `localStorage` |
| `thanks-feedback` | показ вопроса из формы обратной связи |

Модули, которых нет на текущей странице, не должны навешивать обработчики
на отсутствующий DOM.

## Проверки

Логика, которая не трогает DOM, проверяется в Node — без браузера
и за доли секунды:

```powershell
node checks/filters.mjs     # отбор, сортировка, каталог: 73 проверки
node checks/cart.mjs        # корзина и услуга «ПРИНТ»: 54 проверки
node checks/checkout.mjs    # правила полей и сборка заказа: 45 проверок
node checks/feedback.mjs    # форма обратной связи: 57 проверок
node checks/product.mjs     # страница товара: данные, разметка, файлы: 95 проверок
```

Ещё два файла поднимают Chrome сами, потому что им нужны переходы между
страницами, а харнесс выполняет один запрос на одной странице. Адрес
сервера передаётся первым аргументом, по умолчанию — порт 8124:

```powershell
node checks/req-checkout.mjs http://127.0.0.1:8000/       # оформление: 51
node checks/req-feedback-flow.mjs http://127.0.0.1:8000/  # форма вопроса: 22
```

Проверки со страницей запускаются через харнесс
(`~/.dsh/bin/browser.mjs`):

```powershell
python -m http.server 8000                      # сервер из корня проекта
node ~/.dsh/bin/browser.mjs --url http://127.0.0.1:8000/ `
  --request checks/req-cart.mjs --widths 1024   # корзина и окно
```

`checks/req-filters.mjs` и `checks/req-filters-mobile.mjs` проверяют
фильтры, пагинацию и обводку фокуса; им нужен ключ `--press-tab 1`:
программный `.focus()` не включает `:focus-visible`, и проверка цвета
обводки без настоящего ввода с клавиатуры ничего не значит.

`checks/req-button-hover.mjs` проверяет цвет кнопки «В корзину» при
наведении. `:hover` скриптом не включается, поэтому харнессу передаётся
ключ `--mouse-to` с селектором — он прокручивает элемент в вид, двигает
курсор протоколом и только потом выполняет запрос:

```powershell
node ~/.dsh/bin/browser.mjs --url http://127.0.0.1:8000/ `
  --request checks/req-button-hover.mjs --widths 1280 `
  --mouse-to ".goods-new__item:nth-child(1) .product-card__button"
```

`checks/req-feedback.mjs` проверяет показ ошибки в форме вопроса: пустое
поле и короткий текст дают подпись под полем, `is-invalid` и фокус,
а со страницы при этом никто не уходит. Успешную отправку проверять в том же
запуске нельзя: вкладка уходит на `thanks-feedback.html`, и контекст страницы
пропадает — этим занимается `checks/req-feedback-flow.mjs`, который сам
управляет переходами. Ловушка, на которую я наступил: подменить
`location.href`, чтобы перехватить переход, в Chrome нельзя — свойство
неконфигурируемое, переопределение молча не применяется.

`checks/req-feedback-reset.mjs` проверяет, что поле вопроса не воскрешает
прошлый текст. Настоящая перезагрузка тут не годится — она уничтожает
контекст запроса, поэтому проверяются два случая, видимые без перезагрузки:
чистая загрузка и событие `pageshow`, которое браузер шлёт при возврате
из кеша страницы. Настоящий возврат по истории проверяет
`checks/req-feedback-flow.mjs`.

`checks/req-product.mjs` проверяет страницу товара в браузере: раскладку,
выбор размера, добавление товара с размером, галочку услуги и открытие окна
корзины. Видимость точек галереи считается у их контейнера, а не у самой
кнопки: у кнопки `display` свой, и про скрытие контейнера он ничего
не говорит — на этом я уже ошибся один раз.

```powershell
node ~/.dsh/bin/browser.mjs --url http://127.0.0.1:8000/product-pages/klubnichnye-polya.html `
  --request checks/req-product.mjs --widths 375,768,1280
```

`checks/req-thanks-feedback.mjs` проверяет страницу благодарности в двух
состояниях. Сообщение кладётся в `localStorage` и страница перезагружается
ключом `--expr-before`:

```powershell
node ~/.dsh/bin/browser.mjs --url http://127.0.0.1:8000/thanks-feedback.html `
  --request checks/req-thanks-feedback.mjs --widths 1280 `
  --expr-before "localStorage.setItem('cozy-pajamas:message', JSON.stringify({question:'…', createdAt:'2026-03-14T09:30:00.000Z'})); location.reload()"
```

Без `location.reload()` проверка бессмысленна: скрипты страницы выполняются
раньше, чем харнесс получает управление, поэтому запись, сделанная после
загрузки, до модуля уже не дойдёт — и на любой странице был бы показан
пустой блок.

Цвет кнопки берётся из тега `titleColor` в `data.js`, поэтому он есть
у каждого товара секций с фильтрами и у всех шести товаров «Новой коллекции»:
без тега карточка наследует класс `button--pink`, а у него своё правило
`:hover` с тёмным фоном, и розовая кнопка при наведении чернеет.

| Секция | Кнопка в покое | При наведении |
|---|---|---|
| «Новая коллекция», чётные карточки | `--color-pink` `#cd74a2`, белый текст | `--color-pink-light` `#f4d9e8`, текст `--color-dark` |
| «Новая коллекция», нечётные | `--color-blue` `#93b3d6`, белый текст | `--color-blue-light` `#dae2e4`, текст `--color-dark` |
| «Женская коллекция» | как у женских в новой: `--color-pink` | `--color-pink-light`, тёмный текст |
| «Мужская коллекция» | как у мужских в новой: `--color-blue` | `--color-blue-light`, тёмный текст |
| «Другие товары» | `--color-pink` `#cd74a2`, белый текст | `--color-blue` `#93b3d6`, белый текст |

В «Других товарах» тега `titleColor` нет ни у одного товара: там кнопка одна
на всю секцию — розовая, при наведении синяя. Проверяет это пара запросов:
`checks/req-other.mjs` (фон всех 48 кнопок и модификатор) и
`checks/req-other-hover.mjs` (фон под настоящим курсором).

## Шапка и мобильное меню

Логику ведёт `header.js`, стили — `sections/header.css`.

- `.header__nav` помечен `data-nav`, бургер — `data-burger`
- **до 1023px** меню скрыто, бургер раскрывает его наложением на весь экран:
  ссылки столбиком по центру, появление — выездом снизу вверх
- **с 1024px** бургер скрыт, меню стоит строкой в шапке, все пункты видны сразу
- состояние — класс `.is-open` на меню; `aria-expanded` и `aria-label`
  бургера меняются вместе с ним
- меню закрывается бургером, кликом по пункту навигации (переход по якорю
  сохраняется) и кликом по пустому месту наложения
- при прокрутке странице шапке добавляется `.is-scrolled` — снизу появляется
  рамка `1px solid var(--color-blue-light)`

## Секции и якоря

У секций главной страницы есть `id`, совпадающие с якорями меню в шапке:
`#goods-new`, `#goods-women`, `#goods-men`, `#goods-print`, `#goods-other`.

Плавный переход к секции обеспечивает `scroll-margin-top` в `layout.css` —
он компенсирует высоту липкой шапки, чтобы заголовок секции не уезжал под неё.
При добавлении новой секции `id` и `scroll-margin-top` нужно завести вместе.

У сеток каталога классы `goods-<секция>__grid` (у «Других товаров» — `__track`):
по ним `render.js` находит, куда рисовать карточки. Имя секции в `data.js`
(`new`, `women`, `men`, `other`) должно совпадать с классом сетки.
