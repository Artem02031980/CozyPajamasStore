# Магазин уютных пижам

Учебный проект: вёрстка сайта интернет-магазина пижам по готовому дизайн-макету.

**Стек:** чистый HTML, CSS и JavaScript. Без сборщиков, без фреймворков, без PHP.
Корзина и оформление заказа работают только на JavaScript, с сохранением в `localStorage`.
После покупки открывается страница `thanks-cart.html` с благодарностью за покупку.

## Как открыть проект

Только через локальный сервер — двойной клик по `index.html` не сработает:
браузеры блокируют ES-модули на `file://` из-за политики CORS, и скрипты
не запустятся.

```powershell
cd C:\Sites\CozyPajamasStore
python -m http.server 8000     # затем http://localhost:8000
```

Подойдёт и расширение Live Server в VS Code: правый клик по `index.html` →
«Open with Live Server».

## Верстка

Проект верстается по методологии **БЭМ**: имена классов — блоки, элементы (`__`)
и модификаторы (`--`). Например: `.goods-women`, `.product-card__title`,
`.button--accent`. Слои стилей повторяют уровни БЭМ: переиспользуемые блоки
лежат в `blocks/`, привязка блока к месту на странице — в `sections/`.

Пустые папки содержат файл `.gitkeep`: git не хранит пустые каталоги,
без него дерево после клонирования разойдётся с этим описанием. Когда в папке
появятся настоящие файлы, `.gitkeep` можно удалить.

**Макеты в `figma/` в репозиторий не попадают** (папка в `.gitignore`):
файлы весят по 2–3 МБ. Для работы над вёрсткой макеты нужны локально.

## Страницы

| Файл | Что это |
|---|---|
| `index.html` | главная: все секции макета |
| `thanks-cart.html` | «Спасибо за покупку!» после оформления заказа |
| `thanks-feedback.html` | «Спасибо!» после отправки формы «Задайте вопрос» |
| `product-pages/*.html` | страница одного товара; своя для каждой пижамы |

**Страницы товаров статические** — по одному файлу на товар, `id` товара
прописан в разметке самой страницы. Общий стиль — `pages/product.css`,
данные для корзины берутся из `data.js` по этому `id`.

Товарные страницы лежат на уровень глубже корня, поэтому пути к общим файлам
идут через `../` — например `../assets/css/style.css` и `../index.html`.
У `index.html` и страниц благодарности пути обычные, они в корне.

## Скрипты на разных страницах

`script.js` подключается на всех страницах, но каждая страница запускает
только свои модули. Признак страницы — атрибут `data-page` на `<body>`:

| `data-page` | Что запускается |
|---|---|
| `home` | отрисовка секций, фильтры, корзина, форма вопроса |
| `product` | отрисовка товара по `id`, корзина |
| `thanks-cart` | показ состава заказа из `localStorage` |
| `thanks-feedback` | страница подтверждения после формы |

Модули, которых нет на текущей странице, не должны навешивать обработчики
на отсутствующий DOM.

## Шапка и мобильное меню

Разметка шапки готова к подключению логики, сама логика ещё не написана:

- `.header__nav` (контейнер меню) помечен `data-nav`, бургер — `data-burger`
  и несёт `aria-expanded="false"` и `aria-controls="header-nav"`
- до 768px меню скрыто свойством `display: none` в `sections/header.css`,
  а с 768px показывается только активный пункт — остальные пункты появятся
  в раскрытом меню
- **раскрытие меню на мобильном делает JavaScript, которого пока нет** —
  до его появления нажатие на бургер ничего не делает, и меню недостижимо
  с клавиатуры и скринридером (`display: none` убирает его из дерева)

Когда появится скрипт, переключение видимости стоит перевести на класс
`.is-hidden` из `utilities.css` — тогда меню можно будет открывать
и скрывать одним именем, как остальные состояния проекта.

## Секции и якоря

У секций главной страницы есть `id`, совпадающие с якорями меню в шапке:
`#goods-new`, `#goods-women`, `#goods-men`, `#goods-print`, `#goods-other`.

Плавный переход к секции обеспечивает `scroll-margin-top` в `layout.css` —
он компенсирует высоту липкой шапки, чтобы заголовок секции не уезжал под неё.
При добавлении новой секции `id` и `scroll-margin-top` нужно завести вместе.

## Чего в проекте нет

любые `.php` и папка `api/` (заказ имитируется, переход на страницу благодарности делает JS);
`scss/`, `dist/`, `node_modules/`, сборка; `assets/fonts/` (шрифты подключаются ссылкой);
`assets/js/vendor/` (только ванильный JS); `404.html`.
