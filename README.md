# Магазин уютных пижам

Учебный проект: вёрстка сайта интернет-магазина пижам по готовому дизайн-макету.

**Стек:** чистый HTML, CSS и JavaScript. Без сборщиков, без фреймворков, без PHP.
Корзина и оформление заказа работают только на JavaScript, с сохранением в `localStorage`.
После покупки открывается страница `thanks-cart.html` с благодарностью за покупку.

## Как открыть проект

Только через локальный сервер — двойной клик по `index.html` не сработает:
браузеры блокируют ES-модули на `file://` из-за политики CORS, и скрипты
не запустятся.

```powershell
cd C:\Sites\CozyPajamasStore
python -m http.server 8000     # затем http://localhost:8000
```

Подойдёт и расширение Live Server в VS Code: правый клик по `index.html` →
«Open with Live Server».

## Верстка

Проект верстается по методологии **БЭМ**: имена классов — блоки, элементы (`__`)
и модификаторы (`--`). Например: `.goods-women`, `.product-card__title`,
`.button--accent`. Слои стилей повторяют уровни БЭМ: переиспользуемые блоки
лежат в `blocks/`, привязка блока к месту на странице — в `sections/`.

## Страницы

| Файл | Что это |
|---|---|
| `index.html` | главная: шапка, hero, секции каталога, форма, подвал |
| `thanks-cart.html` | «Спасибо за покупку!» после оформления заказа |
| `thanks-feedback.html` | «Спасибо!» после отправки формы «Задайте вопрос» |
| `prints.html` | каталог принтов: 17 карточек, у каждой два состояния рисунка |
| `product-pages/*.html` | страница одного товара; своя для каждой пижамы |

**Каталог живёт в данных, а не в разметке.** Карточки товаров рисует
`render.js` из массива `PRODUCTS` в `data.js`. В `index.html` остаются
только пустые сетки — `<ul class="goods-new__grid">` и такие же для
остальных секций. Чтобы добавить товар, правят `data.js`, а не разметку.

Цена в `data.js` хранится **числом** (`9399`), а не строкой: её нужно
складывать в корзине и сортировать. Печатает её `formatPrice` из
`utils.js` — он расставляет неразрывные пробелы и знак рубля, поэтому
в вёрстке цена выглядит как «9 399 ₽».

### Фильтры и сортировка

Фильтры работают в женской и мужской коллекциях. Группы: тип изделия, возраст,
палитра цветов, цена. Внутри группы условия складываются по «или» (Пижама ИЛИ
Халатик), между группами — по «и» (тип И цвет И цена). Выбор снимается
повторным нажатием, кнопка «Сбросить фильтры» очищает всё сразу.

Логику отбора считает `filters-query.js` — чистые функции без DOM, поэтому
её проверяет `node checks/filters.mjs` без браузера. `filters.js` занимается
разметкой, событиями и состоянием.

**Значения фильтров берутся из самой разметки**, а не из отдельной таблицы:
в `data.js` у товара есть теги `types`, `ages`, `colors`, записанные ровно
теми же строками, что подписи чипсов и `aria-label` кружков в `index.html`.
Добавили чипс — он заработает, если у товаров есть такой тег; тег без чипса
не показывается. Проверка `checks/filters.mjs` следит, чтобы теги и чипсы
не разъехались.

**У каждой коллекции свой словарь фильтров.** Возраст в женской — «Для юных
дам / Для девушек / Для мудрого возраста», в мужской — «Для молодых людей /
Для мужчин / Для мудрого возраста». Теги товаров должны совпадать с чипсами
**своей** секции, иначе фильтр молча не сработает: чипс на странице есть,
но не в этой форме. Проверка сравнивает теги с чипсами по каждой секции
отдельно.

Обводка фокуса у сортировки и у кружков палитры покрашена в акцент секции:
`--color-pink` (#cd74a2) в женской, `--color-blue` (#93b3d6) в мужской.
Цвет задан свойством `--filters-focus` в файлах секций, а сама обводка
остаётся — по ней ориентируются те, кто ходит по странице с клавиатуры.

**У кружков палитры обводка показывает оба состояния, и они различаются
толщиной:** фокус — 5px, выбранный цвет — 3px, в покое обводки нет.
Рамку для выбора использовать нельзя: у `.filters__color` задан шорткат
`border: 1px solid var(--color-transparent)`, и его специфичность (0-2-0) выше,
чем у `.filters__color.is-active { border-color }` (0-1-0), — правило молча
не срабатывало, и выбранный цвет на цветных кружках выглядел как невыбранный.
Обводка же не спорит ни с рамкой белого кружка (она означает только одно:
это белый цвет), ни с состоянием фокуса.

**Теги размечены у всех товаров `women` и `men`** — по таблице из `prompts/`.
У «Новой коллекции» и «Других товаров» тегов нет: фильтров в этих секциях
не бывает, и выдумывать им типы незачем.

**Словарь женской коллекции задаёт таблица.** Состав, элементы фильтра,
цвет и возраст пришли из `prompts/женские пижамы.xlsx`, и чипсы в разметке
перечисляют ровно те значения, что встречаются в данных:

- типы: Брюки, Сорочка, Халатик, Комбинезон, Шорты, Майка, Футболка,
  Платье, Свитшот, Топик (ушли «Пижама» и «Пеньюар» — их больше нет в данных);
- цвета: Чёрный, Белый, Серый, Красный, Розовый, Жёлтый, Зелёный, Голубой,
  Синий, Фиолетовый (ушли «Бежевый» и «Мятный», пришли «Голубой»
  и «Фиолетовый»);
- возраст: Для юных дам, Для девушек, Для мудрого возраста.

В таблице один и тот же цвет был записан и как «Желтый», и как «Жёлтый»,
а элемент — как «Топ» и «Топик». Два чипса на один цвет или на один элемент
сломали бы фильтр, поэтому в данных оставлено одно написание, и оно совпадает
с подписью чипса.

**Словарь мужской коллекции — из `prompts/мужские пижамы.xlsx`**, тем же
порядком:

- типы: Брюки, Сорочка, Пиджак, Майка, Халат, Футболка, Свитшот, Галстук,
  Бабочка (у мужчин «Халат», у женщин «Халатик» — словари у коллекций свои);
- цвета: Чёрный, Белый, Серый, Красный, Розовый, Зелёный, Светло-синий,
  Синий, Фиолетовый, Коричневый, Бордовый (ушли «Жёлтый», «Бежевый»
  и «Мятный»);
- возраст: Для молодых людей, Для мужчин, Для мудрого возраста.

Три товара в таблице переименованы: «Ночной уголь» → «Ночная мгла»,
«Васильковый сон» → «Морской сон», «Песочный берег» → «Белая классика».

Сортировка — выпадающий список над сеткой: порядок каталога, сначала дешёвые,
сначала дорогие, по названию. Ключ сортировки совпадает со значением
`<option>`, поэтому новый вариант добавляется одной строкой в `filters-query.js`
и одним пунктом в разметке. Диапазоны цены разбираются из подписи чипса
(`parsePriceLabel`): «до 4999₽» — верхняя граница, «5000 - 9999₽» — обе.

Если по условиям ничего не нашлось, вместо сетки показывается сообщение,
а пагинация скрывается.

**Женская и мужская коллекции показываются постранично** (`filters.js`).
Сколько карточек на странице, зависит от ширины экрана и совпадает
с числом колонок в сетке:

| Ширина | Колонок | Карточек на странице | Страниц (по 9 товаров) |
|---|---|---|---|
| до 768px | 1 | 5 | 2 |
| 768–1279px | 2 | 6 | 2 |
| с 1280px | 3 | 9 | 1 |

Кнопки страниц строит `filters.js` — их число зависит от количества
товаров, поэтому в разметке лежит только пустой `<ul class="pagination__list">`.
При изменении ширины окна страница пересчитывается: иначе на новом числе
колонок в последнем ряду оставались бы дыры. Пересчёт идёт **только
на переходе через порог** ширины: `resize` приходит и от спрятанной
адресной строки на телефоне, то есть на каждой прокрутке, и сетка
пересобиралась бы по десять раз на экран.

**Номер страницы переживает перезагрузку.** Он лежит в `sessionStorage`
(`cozy-pajamas:pages`, см. `readPages` в `storage.js`), а не только
в памяти модуля: браузер перезагружает вкладку сам — выгружает её из памяти
под давлением и восстанавливает, — и без записи человек, стоявший
на второй странице мужской коллекции, оказывался в начале каталога.
Запись живёт в пределах вкладки: новая вкладка начинается с начала каталога.
Фильтр и сортировка по-прежнему возвращают на первую страницу, и это тоже
запоминается. Проверка — `checks/req-pagination-persist.mjs`.

Клик по кнопке страницы возвращает экран к началу списка товаров — так же,
как при переходе по ссылке пагинации на сайте-образце (jackmenn.ru):
новая страница открывается сверху, и видно первую строку карточек.
Отступ липкой шапки задаёт `scroll-margin-top` у сеток в `layout.css`.

Секции «Новая коллекция» и «Другие товары» показываются целиком,
без пагинации.

### Корзина и оформление заказа

`cart.js` хранит состав корзины, считает суммы и знает правила услуги
«ПРИНТ»; `render-cart.js` собирает разметку; `cart-ui.js` связывает их
со страницей. В хранилище лежат только ссылки на товары — `{id, qty, size}`,
а у позиции «Свой макет» ещё и имя загруженного файла. Название, цену
и фото даёт `data.js`, поэтому правка цены в каталоге сразу видна
в корзине. Заказ (в отличие от корзины) хранит снимок названий и цен:
это документ, и он не должен меняться задним числом.

**Картинку товара в корзине строит скрипт, поэтому адрес считается
от корня проекта** (`assetUrl` в `utils.js`). Прямой путь вида
`assets/images/...` годится на главной, но страница товара лежит
на уровень глубже, и там такой адрес вёл в `product-pages/assets/…` —
фотография не находилась, и позиция появлялась без картинки.

**Размер выбирается до добавления — только у пижам.** Кнопка «В корзину»
в карточке пижамы сразу товар не кладёт: размер там не выбран, и позиция
без размера — это позиция, которую нельзя ни отправить, ни примерить.
Поэтому клик открывает окно выбора размера (`size-picker.js`), и в корзину
товар попадает только после подтверждения. Окно без размера не
подтверждается: под рядами появляется «Выберите размер».

Признак такого поведения — атрибут `data-select-size` у кнопки: его ставит
`render.js`, а `cart-ui.js` по нему отступает. **Ставится он по числу
размеров, а не по названию секции:** у пижам их четыре (S–XXL), у «Других
товаров» один («Единый размер»), и окно для них было бы пустым шагом —
поэтому карточки этой секции кладут товар в корзину сразу, как раньше.
Появится у товара второй размер — окно включится само.
Кнопка «Добавить в корзину» на странице товара (там размер выбирается
на месте) и кнопка услуги «ПРИНТ» тоже работают без окна.

Размеры берутся из данных функцией `getSizes`: свои `sizes` у товара важнее
общих, иначе — список своей секции из `SIZES_BY_SECTION`. У одежды это
S, M, XL, XXL, как в макете; у «Других товаров» — «Единый размер», потому
что подушка и плед не бывают S или M. Один товар в разных размерах — это
две разные позиции корзины, их различает `variantKey` из `utils.js`.

Содержимое окна выровнено по центру: название товара, ряды размеров,
сообщение об ошибке и кнопка стоят на одной оси.

**Акцент окна.** Женская коллекция розовая, как в макете, и это базовые
правила файла. Голубой акцент включается двумя путями:

- `data-section="men"` — у всей мужской коллекции, в тон её карточкам;
- `data-accent="blue"` — у отдельного товара с полем `accent: 'blue'`
  в данных. Так выделены три товара «Новой коллекции»: «Ночная свобода»,
  «Огонь Прометея», «Выгодная философия». У остальных окно розовое.

В голубом акценте название пижамы `--color-blue`, рамка размеров голубая,
при наведении и выборе чипс заливается голубым, а кнопка «Добавить
в корзину» голубая и при наведении розовая. Оба атрибута пишет
`size-picker.js`; отдельных правил для женской коллекции нет — она
работает на базовых розовых.

Услуга «ПРИНТ» бесплатна, когда сумма товаров (без неё самой) дотянула
до порога. Цена и порог заданы в разметке — `data-print-price`
и `data-print-free-from` у ссылки на каталог принтов, — и корзина читает
их оттуда по `data-print-price`. В итогах при этом печатается «бесплатно»,
а не «0 ₽», и итог равен сумме товаров; пока порога не хватает,
показывается, сколько осталось добрать.

**Кнопки добавления услуги на главной больше нет.** Вместо неё ссылка
«Посмотреть каталог принтов» на `prints.html`: принт выбирают в каталоге,
и решение об услуге человек принимает там. Правила подсчёта услуги
в `cart.js` остались — каталог добавляет принт теми же функциями.

**Каталог принтов (`prints.html`).** 17 рисунков дизайнера-иллюстратора
Артёма Мижорниева, каждый по 500 ₽. Данные лежат в `assets/js/prints.js`
(`PRINTS`, `PRINT_PRICE`, `getPrint`, `printLabel`), карточки рисует
`render-prints.js` — как карточки товаров на главной, только из своего
массива: у принта нет ни размеров, ни коллекции, зато есть два состояния
рисунка — `image` (чёрное на белом) и `inverted` (белое на чёрном).

Правила каталога стоят в шапке страницы один раз: принты не цветные,
только нанесение — чёрным на светлую ткань, белым на тёмную. В карточке
два превью рядом («На светлом» / «На тёмном»), название, описание с автором,
цена и «В корзину». Карточки — в один столбец: рисунков много, и в столбце
каждый видно крупно.

В корзине принт — обычная позиция: `id` вида `print-01`, цена из
`PRINT_PRICE`, подпись «Принт 01. Good Morning!», пояснение «Принт для
нанесения» и квадратная картинка (`.cart__image--print`). `cart.js`
находит принт через `getPrint`, поэтому в `data.js` его добавлять не нужно:
принт не товар каталога и в фильтрах пижам не участвует.

**Свой макет — в начале страницы.** Панель «Есть свой рисунок?» стоит
между ценой и правилами нанесения: человеку со своим файлом не нужно
листать 17 карточек. Кнопка — это `label` для скрытого `input[type=file]`,
поэтому окно выбора открывает браузер и работает без JavaScript. Формат
проверяет и позицию «Свой макет» в корзину кладёт `initPrintFileUpload`
из `product.js` — та же функция, что на странице товара, только со своим
префиксом классов пометки (`prints__upload-note` вместо
`product__print-file`).

**Страница — часть сайта, а не отдельная вкладка:** пункт меню «Принты»
ведёт на `prints.html` (на самой странице он помечен `aria-current`),
ссылки «Посмотреть каталог принтов» на главной и «Выбрать из каталога»
на страницах товаров ведут сюда же. Шрифты подключены те же, что
у остальных страниц (Roboto Slab 400 и 700), а скругления взяты из шкалы
сайта: панели и карточки — `--radius-md` (12px), превью — `--radius-sm`
(8px).

**Кнопка «В корзину» в карточке принта** выглядит как в карточках каталога
на главной: компактная, ширина по содержимому, скругление `--radius-xs`
(4px), кегль 14px. Перед подписью стоит белая иконка корзины
(`cart-white.svg` — тот же файл, что на странице товара); подпись обёрнута
в `span[data-cart-label]`, поэтому отзыв «В корзине» меняет текст,
не стирая иконку. Кнопка «Добавить свой макет» в панели над каталогом выглядит как её
близнец на странице товара: скругление --radius-sm (8px), кегль 14px,
высота --control-height, розовая рамка и розовый текст, при наведении —
синяя заливка.

Окно корзины — общий блок `modal`: открытие по `data-modal-open`, закрытие
по ESC, по затемнению и по крестику, ловушка фокуса, возврат фокуса на
кнопку открытия и блокировка прокрутки (`modal.js`).

Форма оформления живёт внутри окна корзины и создаётся тем же
`render-cart.js`. Проверяет и отправляет её `checkout.js`: имя, телефон
(не меньше 10 цифр) и необязательная почта. Адрес перехода после заказа —
в атрибуте `data-checkout-redirect` у формы, поэтому страница товара сможет
вести на свою страницу благодарности.

`thanks-cart.html` читает заказ из `localStorage` (`thanks.js`) и показывает
номер, дату, состав и итог. Если заказа нет — блок «Заказа пока нет» вместо
пустого экрана.

### Покупка в один клик

Кнопка «Купить в один клик» на странице товара не открывает корзину: она
сразу собирает заказ из одного товара (с выбранным размером), кладёт его
в хранилище и уводит на `thanks-cart.html` — человек видит «Спасибо за
заказ!», состав и сумму. Форму при этом заполнять не нужно, поэтому имени
и телефона в заказе нет, и страница благодарности не обращается по имени.

Собирает такой заказ `buildOneClickOrder` в `checkout.js`, обработчик
кнопки — `initBuyNow` оттуда же. **Корзина не трогается**: ни добавляется
в неё товар, ни очищается — то, что человек складывал раньше, остаётся.

**Без размера не проходит ни одна покупка.** Правило одно на обе кнопки
и живёт в `size-guard.js` (`blockWithoutSize`): и «Добавить в корзину»,
и «Купить в один клик» без выбранного размера не срабатывают — под рядом
размеров появляется красное «Выберите размер», фокус переходит на первый
размер, товар в корзину не попадает, заказ не создаётся, вкладка никуда
не уходит. Как только размер выбран, сообщение исчезает само — правило
то же, что у ошибок форм: ошибка уходит, как только её причину исправили.

Требование включает сама разметка: элемента `[data-size-error]` в карточке
товара нет — проверки нет. Поэтому `cart-ui.js` и `checkout.js` не знают
ни про размеры, ни про то, как они устроены на странице: они ищут сообщение
в пределах `<article>` кнопки. Кнопки, которым размер не нужен (карточки
каталога со своим окном выбора, услуга «ПРИНТ», свой макет), под правило
не попадают.

Адрес перехода — в атрибуте `data-buy-now-redirect` у кнопки
(`../thanks-cart.html` со страницы товара), потому что страница лежит
на уровень глубже корня. Проверка `checks/req-checkout.mjs` нажимает кнопку
и убеждается, что вкладка оказалась на странице благодарности, заказ
содержит выбранный размер, а корзина не изменилась. Проверка
`checks/req-product.mjs` нажимает кнопку **без** размера и убеждается
в обратном: сообщение появилось, фокус на размере, заказ не создан.

Проект учебный: заказ создаётся без данных покупателя, и никто ни с кем
не связывается — страница благодарности об этом предупреждает красным.

### Форма обратной связи

Форма «Задайте вопрос» — последняя секция главной (`#feedback`). Сервера
у проекта нет, поэтому `feedback.js` делает то, что на статичном сайте
возможно: проверяет текст, кладёт его в `localStorage`
(`cozy-pajamas:message`) и ведёт на `thanks-feedback.html`.

Проверка вопроса — от 10 до 1000 символов. Нижняя граница отсекает
сообщение, на которое невозможно ответить, верхняя совпадает с `maxlength`
у поля: если границы разойдутся, браузер обрежет текст, который модуль
считает нормальным. У формы стоит `novalidate` — ошибку показывает модуль
подписью под полем, а не системный пузырь браузера, который не перевести
и не оформить. Подпись вынута из потока (`position: absolute`): на 768px
и выше поле и кнопка стоят в одну строку, и третий элемент в ней сломал бы
макет.

Без скрипта форма тоже работает: у неё есть `action` и `method`, браузер
уходит на страницу благодарности обычной отправкой, а та честно говорит,
что сообщение не сохранилось, и зовёт обратно к форме. Пустое состояние
на `thanks-feedback.html` — не заглушка, а рабочий сценарий.

**Поле вопроса всегда начинается пустым.** Браузер сам восстанавливает
значения форм, когда человек возвращается на страницу по кнопке «назад»,
и в поле оказывался прошлый вопрос — рядом с подписью «Напишите вопрос —
поле пустое» это выглядело поломкой. Поэтому у формы и у поля стоит
`autocomplete="off"`, а `feedback.js` очищает поле при запуске и на событие
`pageshow`: возврат из кеша страницы (bfcache) события `load` не вызывает,
модуль при этом уже выполнен.

Кнопки возврата на обеих страницах благодарности оформлены как «Вернуться
к покупкам» в пустой корзине (`.cart__continue`): рамка `1px` розовая,
текст розовый, при наведении и рамка, и текст синие, скругление — токен
`--radius-sm` (8px), а не «пилюля» базовой кнопки. Модификатор
`button--outline` в разметке этих кнопок не ставится: у него свой бежевый
цвет рамки, и он спорил бы с оформлением страницы.

`thanks.js` обслуживает обе страницы благодарности: заказ показывает
`initThanks`, вопрос — `initThanksFeedback`. Текст вопроса печатается
через `textContent`, а не `innerHTML`: это то, что написал человек,
и разметкой оно быть не должно. Переносы строк сохраняет
`white-space: pre-line`.

**У подушки нет размеров и принта**, поэтому со страницы убраны блок
размеров (вместе с сообщением «Выберите размер»), подпись «Добавить принт»
с двумя кнопками и полем файла, а также строка состава.

**Фото стоит по центру карточки по вертикали** на всех страницах, кроме
подушки. Колонка сведений выше снимка — в ней подпись, название, цена,
размеры, две кнопки покупки и «Добавить принт», — и по верхнему краю фото
прилипало к началу карточки, а под ним оставалась пустота. Для этого
галерея растянута на высоту ряда (`align-self: stretch`), а снимок
центрируется в ней (`align-items: center`). У подушки раскладка своя,
там фото по-прежнему прижато к верху — иначе подпись «Другие товары —
подушка» уехала бы от снимка.

**Страница подушки — две колонки, а не три.** У пижам карточка делится
на три части: фото, сведения, описание. У «других товаров» фото и сведения
стоят друг под другом в одной колонке:

1. фото у левого края группы, с 768px — не шире 300px (на телефоне кадр
   и так упирается в ширину экрана, там ограничения нет и он стоит
   с равными полями);
2. под ним подпись «Другие товары — подушка», 16px — мельче названия,
   это подпись к фото, а не заголовок;
3. название одной строкой (с 768px; на телефоне колонка узкая и оно
   переносится), цена и две кнопки покупки шириной до 300px — всё
   по левому краю;
4. вторая колонка — описание и характеристики.

Колонки карточки равны: 440px и 440px на 1280px. **С 1280px содержимое
левой колонки стоит по центру своей половины карточки.** Ширина группы —
300px (по фото и кнопкам), колонка 440px, поэтому слева и справа по 70px;
между фото и описанием — 134px. Группа задана одной grid-колонкой по ширине
содержимого и центрируется целиком, чтобы у фото, подписи, названия, цены
и кнопок был общий левый край — иначе края получились бы рваными.
До 1280px карточка одноколоночная, там центрировать нечего.

**С карточки каталога на них ведёт ссылка.** Адрес страницы хранится
в данных — поле `page` у товара, — поэтому `render.js` подставляет его
в `href`, а товарам без страницы оставляет прежнюю заглушку
(`product-pages/`). Появится ещё одна страница — у её товара добавляется
одно поле, разметку карточек править не нужно.

**Колонке с кнопками нужен минимум ширины.** С 1280px первая половина
карточки делится на фото и сведения: фото занимает свою ширину, сведения —
остальное. Кадры у товаров разной пропорции: у пижам 385×1159 (при
max-height 520px это 173px ширины), а у «Нежного счастья» 576×1160 — уже
258px. В прежней раскладке такому фото доставалось 258px из 440, а кнопкам
оставалось 158px: подписи «Добавить в корзину» и «Выбрать из каталога»
вылезали за край. Поэтому у колонки сведений минимум 220px
(`grid-template-columns: auto minmax(220px, 1fr)`): в тесноте сжимается
фото, а не кнопки. Пижамные страницы это не задело — у них сведениям
и так достаётся 235px и 243px.

**У мужской коллекции акцент обратный: розовое и голубое меняются
местами.** Разметка у страниц одна, поэтому цвет задаёт вид товара
(`data-section`), а не классы в HTML: в конце `product.css` лежит блок
`body[data-section='men']`, где название и кнопки голубые, а пометка
размера и наведение розовые. Иконки тоже свои — голубая `icon-catalog_blue.svg`
у кнопки каталога и голубое кольцо-разделитель.

**У «других товаров» бежевое только название.** Там же в `product.css`
лежит блок `body[data-section='other']`: название бежевое, а кнопки —
общей палитры, как у пижам: «Добавить в корзину» розовая и при наведении
синеет; у контурной «Купить в один клик» розовая рамка и розовый текст,
а при наведении синяя заливка с синей рамкой. Сначала кнопки были
бежевыми, но текст на бежевом не читался, и владелец проекта вернул
общие цвета.

**Размеры живут в данных**, а не только в разметке: то же окно выбора
размера открывается с карточки на главной, и там должны быть те же
значения (`sizes` у товара в `data.js`). У подушки размеров нет — окно
предлагает один «Единый размер», и на странице блока размеров тоже нет.

**Разметка статична: товар, фото и характеристики стоят в HTML, а не
рисуются скриптом.** Страница должна читаться и без JavaScript, поэтому
`product.js` добавляет только поведение: листание галереи, выбор размера
и проверку формата выбранного файла макета. Обратная сторона — данные
дублируются в `data.js` и в разметке, и расхождение ловит
`checks/product.mjs`: он сверяет название, цену, описание, характеристики
и размеры фото с файлом.

Данные для страницы лежат отдельными полями товара в `data.js` — `sizes`,
`description`, `details`. Поля необязательные: у остальных 140 товаров
их нет, и страница должна работать без них.

| В макете | В проекте | Почему |
|---|---|---|
| Стрелки листания | Стрелки есть, точек нет; до 767px у краёв галереи, с 768px у краёв карточки. На всех страницах пижам это ссылки на соседний товар | Кадр один, листать нечего: в «Новой», «Женской» и «Мужской» коллекциях стрелки ведут по каталогу — порядок тот же, что у карточек на главной. У подушки стрелки остались выключенными кнопками — задел под вторые ракурсы. Точки при одном кадре ничего не показывали — убраны совсем |
| Кнопки в строку | В столбик на всю ширину колонки | Две кнопки занимают 462px, колонка информации — 312px: в строку на 768px появлялась горизонтальная прокрутка страницы |

| Галочка «Добавить услугу нанесения принта» | Убрана; вместо неё текст «Добавить принт:» | Услуга «ПРИНТ» добавляется кнопкой в секции принтов главной, а на странице товара человек выбирает макет. Галочка дублировала то же действие неочевидным способом |

**Ширина карточки.** До 767px — 720px, как в макете 320. С 768px карточка
занимает всю ширину контейнера и растёт вместе с экраном, пока не упрётся
в 1200px: 704px на 768px, 836 на 900, 960 на 1024, 1088 на 1152, 1200px
с 1264. С 1280px ширина та же, но карточка делится на две колонки.

**Стрелки.**

- до 767px — внутри галереи, у её краёв, по центру фото (как в макете 320);
- с 768px — внутри карточки, но у её краёв. Привязка переезжает с галереи
  на карточку: у `.product__gallery` `position` снимается (static),
  у `.product__card` появляется relative.

**Куда ведут.** У товаров «Новой», «Женской» и «Мужской» коллекций кадр
один, поэтому стрелки не листают фото, а ведут на соседний товар раздела —
в порядке `data.js`, то есть в том же порядке, в каком карточки стоят
на главной:

| | Левая стрелка | Правая стрелка |
|---|---|---|
| первая страница раздела | нет | на следующий товар |
| средняя | на предыдущий | на следующий |
| последняя | на предыдущий | нет |

Это обычные ссылки `<a href>`, а не кнопки: они работают и без скрипта,
и браузер показывает адрес при наведении. Подпись у них общая —
«Предыдущий товар» и «Следующий товар»: название соседа в подпись
не попадает, иначе на странице оказывались бы данные чужого товара.
Добавили страницу в середину раздела — придётся поправить стрелки
у неё и у двух соседей; расхождение ловит `checks/product-arrows.mjs`
(обходит три цепочки целиком).

У подушки стрелки остались выключенными кнопками: в «Других товарах»
страница одна, соседей у неё нет. `product-arrows.mjs` это проверяет.

Отступы заданы тремя величинами у `.product__card`, и от них же считаются
боковые поля карточки — так стрелка не наезжает ни на фото, ни на кнопки:

| Величина | Значение | Что задаёт |
|---|---|---|
| `--arrow-inset` | `--space-20` (20px), с 1280px `--space-32` (32px) | отступ стрелки от края карточки |
| `--arrow-size` | `--space-32` (32px) | ширина стрелки |
| `--arrow-gap` | `--space-16` (16px), с 1280px `--space-64` (64px) | зазор между стрелкой и содержимым |

Боковые поля карточки — `calc(--arrow-inset + --arrow-size + --arrow-gap)`:
68px от 768px и 128px от 1280px. Замеры: отступ стрелки от края карточки
20px (32px от 1280px) с обеих сторон, по вертикали стрелка по центру
карточки.
На 1280px вертикальные поля свои (40px), поэтому там задан `padding-block`,
а не `padding`: короткая запись сбросила бы боковые поля под стрелки.

На 1280px зазор растёт до 64px — из него и берётся воздух между стрелками
и содержимым: фото сдвигается вправо на 60px (96 → 156px от края карточки),
а колонка «Описание» на столько же сокращается справа (512 → 452px).
Колонки при этом сужаются на 48px каждая, и всё содержимое остаётся
целым: заголовок в две строки, кнопки 247px, горизонтальной прокрутки нет.

**С 1280px карточка делится на две колонки.** Граница проходит между кнопкой
«Добавить свой макет» и заголовком «Описание»: слева фото и всё нужное для
покупки, справа описание и характеристики. В разметке это две обёртки,
`.product__main` и `.product__specs`; до 1280px они идут одна под другой,
и описание стоит следом за кнопками, как в макете. Карточка при этом
становится ниже: 600px на 1280px против 938px на 1279px.

**Нанесение принта.** Галочки услуги на странице больше нет — вместо неё
подпись «Добавить принт:» и две кнопки:

- **«Выбрать из каталога»** — ссылка на `prints.html`, страницу каталога
  принтов с 17 рисунками;
- **«Добавить свой макет»** — `label` для скрытого `input[type=file]`,
  поэтому системное окно выбора открывает сам браузер и работает это без
  JavaScript. В `accept` разрешены PDF, JPG, PNG, PSD и TIFF.

`accept` — только подсказка для диалога: в нём можно переключиться
на «Все файлы». Поэтому формат проверяет и `product.js`
(`checkPrintFile`): неподходящий файл не остаётся в поле, а под кнопками
появляется красное «Файл не подходит. Нужен PDF, JPG, PNG, PSD или TIFF».

**Подходящий макет уходит в корзину** позицией «Свой макет»
(`CUSTOM_PRINT_ID` в `cart.js`). Цены у неё нет: стоимость печати зависит
от макета, её называет менеджер, поэтому сумма нулевая, в корзине стоит
«по согласованию», а рядом — пометка «Стоимость уточнит менеджер: свяжется
с вами отдельно». Под кнопками при этом появляется подпись с иконкой файла:
«Макет добавлен в корзину: макет.pdf…». Заявка одна на все макеты —
повторная загрузка заменяет файл, а не плодит вторую позицию.

Само поле скрыто визуально, но остаётся в порядке табуляции; когда фокус
приходит к нему, кнопка-подпись получает обводку — иначе с клавиатуры
не видно, где фокус.

У обеих кнопок при наведении синяя заливка. Иконка каталога при этом
меняется на белую (`icon-catalog_white.svg`): цвет внутри SVG зашит,
`currentColor` на него не действует, поэтому подменяется файл — тот же приём,
что у иконок соцсетей в подвале. Обе иконки в ряду кнопок одного размера,
16px: файл каталога 11×11 растягивается через `background-size: contain`,
а `flex: none` не даёт ему ужиматься вместе с текстом кнопки.

**Выбранный размер** появляется строкой под названием — «Размер M» — мельче
названия (18px против 30px) и голубым. В само название размер
не дописывается: имя товара от выбора не меняется. Нет выбора — строки нет
совсем (атрибут `hidden`), поэтому лишнего отступа над ценой не остаётся.

**Состав** — первая строка под заголовком «Описание»: «Брюки + Сорочка +
Майка». Жирный, в отличие от обычного текста описания: это перечень частей
товара, а не начало фразы. Строка берётся из того же поля `subtitle`
в `data.js`, что стоит меткой под названием в карточке каталога, и
`checks/product.mjs` сверяет её с данными — иначе после смены состава
страница показывала бы старый.

**Декоративный разделитель** — кольцо между описанием и характеристиками,
40×40, по левому краю колонки, как текст описания над ним. Файл свой
у каждого вида товара (`icon-circle_women.svg`, `icon-circle_men.svg`,
`icon-circle_other.svg` в `assets/images/icons`), и выбирается он так же,
как фон страницы — по `data-section` у `<body>`: кольцо в тон своей
коллекции (розовое, голубое, бежевое). Для скринридера это пустое место,
поэтому у элемента `aria-hidden="true"` и нет текста.

**Фон страницы свой у каждого вида товара.** В `assets/images/product-page`
лежат `bg_women.png`, `bg_men.png` и `bg_other.png` (1536×864). Какой взять,
решает атрибут `data-section` у `<body>` — он же совпадает с именем секции
в каталоге: `women`, `men`, `other`. Цвет подложки под фоном тоже свой
у вида (`--color-pink-light`, `--color-blue-light`, `--color-beige-light`),
чтобы страница не мигала белым, пока картинка грузится, и чтобы на мобильном
остался верный тон.

Фон включается с 768px: за карточкой во всю ширину его не видно, а каждый
файл весит около 1.4 МБ. Проверить другой вид товара можно, не делая
страницу: поменять `data-section` в инспекторе.

**Фон закреплён слоем, а не через `background-attachment: fixed`.** Раньше
картинку держал сам `body` с `background-attachment: fixed`. В Chrome
на Windows такой фон перерисовывается целиком на каждом кадре прокрутки,
и на картинке в 1.4 МБ это видно как мигание экрана. Теперь картинку рисует
`body::before` с `position: fixed; inset: 0; z-index: -1`: она так же
стоит на месте, пока содержимое едет, но композитор держит её отдельным
слоем и не перерисовывает. `pointer-events: none` — чтобы слой не ловил
клики. Проверка в `checks/product.mjs` следит, чтобы `background-attachment:
fixed` не вернулся.

**Файлы из макета.** `icon-catalog.svg` → `assets/images/icons/icon-catalog.svg`
— иконка на кнопке «Выбрать из каталога». `icon-circle.svg`
(точка-индикатор галереи) в проект не попал: точки убраны, при одном кадре
они ничего не показывали. `icon-cart.svg` тоже не добавлен: это та же
корзина, что уже лежит в `cart-white.svg`, только с другим вьюбоксом
и без обёртки Illustrator, — два файла с одной иконкой разъехались бы
по масштабу.

Товарные страницы лежат на уровень глубже корня, поэтому пути к общим файлам
идут через `../` — например `../assets/css/style.css` и `../index.html`.
У `index.html` и страниц благодарности пути обычные, они в корне.

## Скрипты на разных страницах

`script.js` подключается на всех страницах, но каждая страница запускает
только свои модули. Признак страницы — атрибут `data-page` на `<body>`:

| `data-page` | Что запускается |
|---|---|
| `home` | отрисовка секций, фильтры, корзина, оформление заказа, форма вопроса |
| `product` | размеры, выбор файла макета, корзина, покупка в один клик |
| `thanks-cart` | показ состава заказа из `localStorage` |
| `thanks-feedback` | показ вопроса из формы обратной связи |
| `prints` | пока только шапка с меню, окно корзины и её счётчик |

Отдельно, до выбора набора скриптов, запускается `footer-year.js`:
он ставит текущий год в подпись подвала там, где есть маркер
`data-copyright-year`. Сейчас маркер есть только на страницах товаров
(«© 2023 - 2026»), главная и принты остаются с короткой подписью «© 2023».
Число в разметке статичное — страница читается и без скрипта, — а модуль
меняет его на текущий год при загрузке, чтобы в январе не остался
прошлогодний.

Модули, которых нет на текущей странице, не должны навешивать обработчики
на отсутствующий DOM.

Проверки со страницей запускаются через харнесс
(`~/.dsh/bin/browser.mjs`):

```powershell
python -m http.server 8000                      # сервер из корня проекта
node ~/.dsh/bin/browser.mjs --url http://127.0.0.1:8000/ `
  --request checks/req-cart.mjs --widths 1024   # корзина и окно
```

`checks/req-filters.mjs` и `checks/req-filters-mobile.mjs` проверяют
фильтры, пагинацию и обводку фокуса; им нужен ключ `--press-tab 1`:
программный `.focus()` не включает `:focus-visible`, и проверка цвета
обводки без настоящего ввода с клавиатуры ничего не значит.

`checks/req-button-hover.mjs` проверяет цвет кнопки «В корзину» при
наведении. `:hover` скриптом не включается, поэтому харнессу передаётся
ключ `--mouse-to` с селектором — он прокручивает элемент в вид, двигает
курсор протоколом и только потом выполняет запрос:

```powershell
node ~/.dsh/bin/browser.mjs --url http://127.0.0.1:8000/ `
  --request checks/req-button-hover.mjs --widths 1280 `
  --mouse-to ".goods-new__item:nth-child(1) .product-card__button"
```

`checks/req-feedback.mjs` проверяет показ ошибки в форме вопроса: пустое
поле и короткий текст дают подпись под полем, `is-invalid` и фокус,
а со страницы при этом никто не уходит. Успешную отправку проверять в том же
запуске нельзя: вкладка уходит на `thanks-feedback.html`, и контекст страницы
пропадает — этим занимается `checks/req-feedback-flow.mjs`, который сам
управляет переходами. Ловушка, на которую я наступил: подменить
`location.href`, чтобы перехватить переход, в Chrome нельзя — свойство
неконфигурируемое, переопределение молча не применяется.

`checks/req-feedback-reset.mjs` проверяет, что поле вопроса не воскрешает
прошлый текст. Настоящая перезагрузка тут не годится — она уничтожает
контекст запроса, поэтому проверяются два случая, видимые без перезагрузки:
чистая загрузка и событие `pageshow`, которое браузер шлёт при возврате
из кеша страницы. Настоящий возврат по истории проверяет
`checks/req-feedback-flow.mjs`.

`checks/req-product.mjs` проверяет страницу товара в браузере: раскладку,
выбор размера, добавление товара с размером, выбор файла макета (подходящий,
неподходящий и сброс поля) и открытие окна корзины. Видимость точек галереи
считается у их контейнера, а не у самой кнопки: у кнопки `display` свой,
и про скрытие контейнера он ничего не говорит — на этом я уже ошибся
один раз.

Файл в поле подкладывается через `DataTransfer` — так же, как его выбрал бы
человек. Подсветку кнопки при фокусе с клавиатуры так проверить нельзя:
`:focus-visible` не срабатывает от программного `focus()` и от `--press-tab`
в headless. Правило в CSS есть, но глазами его видно только в живом браузере
при настоящем Tab.

```powershell
node ~/.dsh/bin/browser.mjs --url http://127.0.0.1:8000/product-pages/klubnichnye-polya.html `
  --request checks/req-product.mjs --widths 375,768,1280
```

`checks/req-thanks-feedback.mjs` проверяет страницу благодарности в двух
состояниях. Сообщение кладётся в `localStorage` и страница перезагружается
ключом `--expr-before`:

```powershell
node ~/.dsh/bin/browser.mjs --url http://127.0.0.1:8000/thanks-feedback.html `
  --request checks/req-thanks-feedback.mjs --widths 1280 `
  --expr-before "localStorage.setItem('cozy-pajamas:message', JSON.stringify({question:'…', createdAt:'2026-03-14T09:30:00.000Z'})); location.reload()"
```

Без `location.reload()` проверка бессмысленна: скрипты страницы выполняются
раньше, чем харнесс получает управление, поэтому запись, сделанная после
загрузки, до модуля уже не дойдёт — и на любой странице был бы показан
пустой блок.

Цвет кнопки берётся из тега `titleColor` в `data.js`, поэтому он есть
у каждого товара секций с фильтрами и у всех шести товаров «Новой коллекции»:
без тега карточка наследует класс `button--pink`, а у него своё правило
`:hover` с тёмным фоном, и розовая кнопка при наведении чернеет.

| Секция | Кнопка в покое | При наведении |
|---|---|---|
| «Новая коллекция», чётные карточки | `--color-pink` `#cd74a2`, белый текст | `--color-pink-light` `#f4d9e8`, текст `--color-dark` |
| «Новая коллекция», нечётные | `--color-blue` `#93b3d6`, белый текст | `--color-blue-light` `#dae2e4`, текст `--color-dark` |
| «Женская коллекция» | как у женских в новой: `--color-pink` | `--color-pink-light`, тёмный текст |
| «Мужская коллекция» | как у мужских в новой: `--color-blue` | `--color-blue-light`, тёмный текст |
| «Другие товары» | `--color-pink` `#cd74a2`, белый текст | `--color-blue` `#93b3d6`, белый текст |

В «Других товарах» тега `titleColor` нет ни у одного товара: там кнопка одна
на всю секцию — розовая, при наведении синяя. Проверяет это пара запросов:
`checks/req-other.mjs` (фон всех 48 кнопок и модификатор) и
`checks/req-other-hover.mjs` (фон под настоящим курсором).

## Шапка и мобильное меню

Логику ведёт `header.js`, стили — `sections/header.css`.

- `.header__nav` помечен `data-nav`, бургер — `data-burger`
- **до 1023px** меню скрыто, бургер раскрывает его наложением на весь экран:
  ссылки столбиком по центру, появление — выездом снизу вверх
- **с 1024px** бургер скрыт, меню стоит строкой в шапке, все пункты видны сразу
- состояние — класс `.is-open` на меню; `aria-expanded` и `aria-label`
  бургера меняются вместе с ним
- меню закрывается бургером, кликом по пункту навигации (переход по якорю
  сохраняется) и кликом по пустому месту наложения
- при прокрутке странице шапке добавляется `.is-scrolled` — снизу появляется
  рамка `1px solid var(--color-blue-light)`
- на `.header` **нельзя** ставить `will-change`, `transform`, `filter`,
  `perspective` и `contain`: любое из них делает шапку содержащим блоком
  для фиксированных потомков, а меню-наложение — это `position: fixed`
  внутри шапки. С таким свойством меню сжимается до высоты шапки, и на
  экране остаётся полоска с одним пунктом. Стерегут `checks/header.mjs`
  (правила CSS) и `checks/req-header.mjs` (геометрия наложения в браузере)

## Секции и якоря

У секций главной страницы есть `id`: `#goods-new`, `#goods-women`,
`#goods-men`, `#goods-print`, `#goods-other`. Пункты меню в шапке ведут
на них — кроме «Принтов»: с появлением каталога этот пункт ведёт
на `prints.html`, потому что из меню человек ищет каталог рисунков,
а не описание услуги. Якорь `#goods-print` остался у секции услуги
на главной: на него по-прежнему можно ссылаться изнутри сайта.

Плавный переход к секции обеспечивает `scroll-margin-top` в `layout.css` —
он компенсирует высоту липкой шапки, чтобы заголовок секции не уезжал под неё.
При добавлении новой секции `id` и `scroll-margin-top` нужно завести вместе.

У сеток каталога классы `goods-<секция>__grid` (у «Других товаров» — `__track`):
по ним `render.js` находит, куда рисовать карточки. Имя секции в `data.js`
(`new`, `women`, `men`, `other`) должно совпадать с классом сетки.

## Подвал

`footer.css`, общий для всех страниц: одна строка «ООО «Магазин уютных
пижам» © 2023» по центру, отступы `--space-40` сверху и снизу.
На страницах товаров к подписи добавлен текущий год: «© 2023 - 2026»,
число обновляет `footer-year.js`.

Фон у подвала свой на каждом типе страниц. Правила лежат в `footer.css`
и привязаны к `body[data-page]`, поэтому новые страницы товаров
и новые страницы вообще подхватывают оформление сами.

| Страница | Фон | Подпись | Контраст |
|---|---|---|---|
| главная (`home`) | `--color-blue-light` #dae2e4 | `--color-dark` | 6.5:1 |
| страницы товаров (`product`) | `--color-dark` #4c4c4c | `--color-grey-blue` | 7:1 |
| каталог принтов (`prints`) | `--color-beige-light` #e9e2d0 | `--color-dark` | 6.65:1 |

Это правки владельца проекта: раньше подвал был синим с белой подписью
(контраст 2.17:1, ниже нормы WCAG AA), потом светло-бежевым. Голубой
подвал на главной совпадает по тону с секцией формы обратной связи — она
того же `--color-blue-light`, — поэтому видимой границы между секцией
и подвалом нет; если нужна полоса-разделитель, её надо добавлять
отдельным правилом.

**На страницах товаров подвал тёмный**, правило висит на
`body[data-page='product']`: новые страницы товаров получают его сами.
Страницы благодарности подвала не имеют вовсе.
