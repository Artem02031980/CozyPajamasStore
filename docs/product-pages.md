# Инструкция: как сверстать страницу товара

Документ для нового агента. Читается целиком перед любой работой
со страницами товаров. Проект — `C:\Sites\CozyPajamasStore`.
Правила проекта и список команд — в `AGENTS.md` в корне.

Страницы товаров лежат в `product-pages/`. Сейчас их девять, и все
сделаны по одному образцу, поэтому новая страница — это копия
подходящего шаблона с заменой данных товара. Придумывать разметку
заново не нужно и нельзя: карточка, шапка, корзина, принт и подвал
должны совпадать с остальными страницами до класса.

## Быстрый старт

1. Найти товар в `data.js` по названию; если адрес страницы уже есть —
   остановиться и спросить.
2. Выбрать шаблон по виду товара: женский / мужской / «другие товары».
3. Скопировать шаблон в `product-pages/<транслитерация>.html`.
4. Заменить: `<title>`, meta description, фото (`src`/`alt`/`width`/
   `height`), подпись, название, цену, чипы размеров, `id` у кнопок
   покупки, состав, описание, характеристики.
5. Дописать в запись товара `page`, `description`, `details`.
6. Обновить `checks/links.mjs`, добавить `checks/product-<slug>.mjs`.
7. Прогнать статические проверки и браузерные замеры на 375, 768, 1024,
   1280, 1440; обновить README; закоммитить только свои файлы.

## 1. Анатомия страницы

```
product-pages/<файл>.html
├── <head>
│   ├── <title>Название — пижама женская | Магазин уютных пижам</title>
│   ├── <meta name="description" content="Пижама женская «…»: … Размеры … 7 699 ₽.">
│   ├── favicon, шрифты Roboto Slab, ../assets/css/style.css
├── <body data-page="product" data-section="women|men|other">
│   ├── .root
│   │   ├── <header class="header"> — тот же, что на главной
│   │   ├── <main class="main">
│   │   │   └── <section class="product"> → .product__inner → article.product__card
│   │   │       ├── .product__main                     ← первая колонка
│   │   │       │   ├── .product__gallery               фото + две стрелки (обе disabled:
│   │   │       │   │                                    кадр один)
│   │   │       │   └── .product__info                  сведения и покупка
│   │   │       │       ├── .product__subtitle          подпись: тип + возраст
│   │   │       │       ├── h1.product__title           название
│   │   │       │       ├── .product__chosen-size       пометка выбранного размера (hidden)
│   │   │       │       ├── .product__price             цена
│   │   │       │       ├── .product__sizes             размеры + сообщение «Выберите размер»
│   │   │       │       ├── .product__buttons           «Добавить в корзину» + «Купить в один клик»
│   │   │       │       └── .product__print*            «Добавить принт»: каталог + свой макет
│   │   │       └── .product__specs                    ← вторая колонка
│   │   │           ├── .product__block                 «Описание:» + состав + текст
│   │   │           ├── .product__divider               кольцо-разделитель (по data-section)
│   │   │           └── .product__block                 «Характеристики» + dl.product__details
│   │   ├── <footer class="footer">                     тёмный; подпись
│   │   │                                               «© 2023 - <span data-copyright-year>»
│   │   │                                               год обновляет footer-year.js
│   │   └── модальное окно корзины (data-modal="cart")
│   └── <script type="module" src="../assets/js/script.js">
```

Пути — через `../`: страница лежит на уровень глубже корня.

Стили страницы — `assets/css/pages/product.css`. Ничего своего в разметке
не стилизуется: акцент, фон и кольцо выбираются по `data-section`.

## 2. Три типа страниц

| | Женская | Мужская | Другие товары |
|---|---|---|---|
| Шаблон | `klubnichnye-polya.html` | `myatnyy-vecher.html` | `lyanyanoy-damask.html` |
| `data-section` | `women` | `men` | `other` |
| Акцент | название розовое, кнопка розовая, наведение синее | название голубое, кнопка голубая, наведение розовое | название бежевое, кнопки общей палитры (розовая/розовый контур) |
| Размеры | есть: набор из `data.js` | есть: набор из `data.js` | нет: ни блока, ни `data-size-error` |
| Пометка выбранного размера | есть | есть | нет |
| Блок принта | есть | есть | нет |
| Строка состава в описании | есть | есть | нет |
| Характеристик | 5 | 7 (плюс узор и комплектация) | 7 по товару (у подушки: назначение, размер, материал, наполнитель, узор, уход, коллекция) |
| Раскладка 1280px | фото + сведения + описание (три колонки) | то же | две колонки: фото и сведения одной колонкой по центру |
| Фото | ширина по кадру, высота до 520px | то же | до 300px, по левому краю группы |

Секция каталога и вид страницы — разные вещи. У шести страниц «Новой
коллекции» (`section: 'new'` в данных) `data-section` всё равно `women`
или `men`: фон, кольцо и акцент берутся из вида изделия, а не из секции
каталога. Если товар женский — женский шаблон, мужской — мужской.

## 3. Порядок работы

Девять шагов, ни один нельзя пропустить. Шаги 1–2 — только чтение,
ничего не менять, пока не выбраны товар и шаблон.

### Шаг 1. Найти товар в `assets/js/data.js`

В PowerShell inline-код с кавычками ломается, поэтому любой скрипт —
файлом в `$env:TEMP` и запуском `node файл.mjs`. Это правило для всех
команд в проекте.

```js
// $env:TEMP\find.mjs — поиск товара по названию
import { PRODUCTS } from 'file:///C:/Sites/CozyPajamasStore/assets/js/data.js';
const found = PRODUCTS.filter((p) => p.title.includes('Солнце'));
console.log(JSON.stringify(found, null, 2));
```

```powershell
node "$env:TEMP\find.mjs"
```

Нужны поля: `id`, `section`, `title`, `subtitle` (состав), `types`, `ages`,
`colors`, `price`, `image`, `alt`, `width`, `height`, `sizes` (если есть),
`page` (если страница уже заведена — тогда работу не начинать, а спросить,
что менять).

Пример — «Солнце»:

```js
{ id: 'goods-women-01', section: 'women', title: 'Солнце',
  titleColor: 'pink', subtitle: 'Брюки + Сорочка',
  types: ['Брюки', 'Сорочка'], ages: ['Для девушек'], colors: ['Жёлтый'],
  price: 7699, image: 'assets/images/products/women/w01.png',
  alt: 'Жёлтая полупрозрачная пижама в белый горошек',
  width: 294, height: 1034 }
```

**Если товара в данных нет** — сначала добавить запись в `data.js`
(это отдельная правка), затем страницу. Фото искать в
`assets/images/products/<секция>/`, взять его реальные `width` и `height`
из файла. Если фото нет — остановиться и спросить владельца, не
подставлять чужой кадр.

### Шаг 3. Скопировать шаблон в новый файл

Имя — транслитерация названия строчными латинскими буквами через дефис:
`klubnichnye-polya`, `myatnyy-vecher`, `lyanyanoy-damask`,
`nezhnoe-schaste`, `spokoynaya-noch-iv`, `rozovye-perekrestki`.
Пример: `product-pages/solntse.html`.

### Шаг 4. Заменить данные в разметке

Менять только перечисленное. Всё остальное — разметка, комментарии
про корзину, принт, шапку — остаётся как в шаблоне. Подпись подвала
с годом (`© 2023 - <span data-copyright-year>2026</span>`) тоже
не трогать: рядом с ней нет данных товара, а год подставляет
`footer-year.js`.

| Что | Как искать | Чем заменить |
|---|---|---|
| `<title>` | `<title>Клубничные поля — пижама женская | Магазин уютных пижам</title>` | `<Название> — пижама женская | …` (для пеньюара — `пеньюар женский`) |
| meta description | `content="Пижама женская «Клубничные поля»: …` | `Пижама женская «<Название>»: <состав словами>. Размеры <набор>. <цена> ₽.` |
| вид товара | `<body data-page="product" data-section="women">` | для женских/мужских оставить, для подушки `other` |
| фото | `src="../assets/images/products/women/w03.png"` + `alt` + `width` + `height` | из данных товара, размеры — настоящие пиксели файла |
| подпись | `<p class="product__subtitle">Пижама для девушек</p>` | `<types[0]> <ages[0] со строчной: для девушек>` |
| название | `<h1 class="product__title">Клубничные поля</h1>` | название из данных |
| цена | `<p class="product__price">12 199 ₽</p>` | цена: разряды через обычный пробел, `7 699 ₽` |
| размеры | блок `.product__sizes-list` | ровно `getSizes(product)`, по чипу на размер |
| покупка | `data-cart-add="goods-women-03"`, `data-buy-now="goods-women-03"` | `id` товара в оба места |
| состав | `<p class="product__composition">Брюки + Сорочка + Майка</p>` | `subtitle` из данных, слово в слово |
| описание | `<p class="product__text">…</p>` | текст из поля `description` (см. шаг 5) |
| характеристики | `<dl class="product__details">…</dl>` | из поля `details`, по паре `<dt>/<dd>` на строку |

**Подпись над названием** собирается из данных: `types[0]` плюс возрастная
группа со строчной буквы. «Пижама для девушек», «Пижама для мужчин»,
«Пижама для молодых людей», «Пеньюар для девушек». У подушки своя
конструкция: «Другие товары — подушка» (секция плюс тип строчными).

**Размеры.** Чипы обязаны совпадать с `getSizes(product)` — это тот же
набор, что показывает окно выбора размера на главной. У мужского шаблона
в макете стоят `M, XL, XXL, XXXL`, а у большинства мужских товаров набор
секции `S, M, XL, XXL`: если не заменить, товар добавится с размером,
которого нет в окне выбора. Наборы по секциям — `SIZES_BY_SECTION`
в `data.js`: `new/women/men` → `S, M, XL, XXL`, `other` → `Единый размер`.

**Если размеров у товара нет** (`other`) — удалить блок `.product__sizes`
целиком вместе с `<p data-size-error>`, удалить `.product__chosen-size`
и `data-cart-size` у обеих кнопок. Правило «без размера не покупаем»
включается наличием `[data-size-error]`, поэтому без размеров его быть
не должно.

### Шаг 5. Записать данные страницы в `data.js`

К записи товара добавляются поля (у «Клубничных полей» и всех девяти
страниц они есть):

```js
    page: 'product-pages/solntse.html',
    description:
      'Жёлтая полупрозрачная пижама с белым горошком — сорочка с V-вырезом и брюки. …',
    details: [
      { name: 'Сезон', value: 'Круглый год' },
      { name: 'Материал', value: 'Шифон' },
      { name: 'Состав материала', value: '100% полиэстер' },
      { name: 'Коллекция', value: 'Весна-Лето 2024' },
      { name: 'Стиль', value: 'Домашний, повседневный' },
    ],
```

- `description` — 2–4 предложения по фотографии: что за изделие, из чего,
  что с ним удобно. Без рекламных восклицаний.
- `details` — у женских страниц 5 строк (сезон, материал, состав,
  коллекция, стиль), у мужских 7 (плюс узор и комплектация). Для подушки
  набор свой: назначение, размер, материал, наполнитель, узор, уход.
- Текст в `description`/`details` и текст в разметке должны совпадать
  символ в символ — это проверяет чек-лист (регистр, тире, ё).
- `sizes` добавляется только если набор отличается от секционного.
- `width`/`height` — настоящие пиксели файла фото.

### Шаг 6. Обновить проверки

1. `checks/links.mjs` — там перечислены все товары с адресами страниц
   (`withPage.map(...)`) и таблица `NEW_PAGES`. Добавить новый `id`
   в нужный список и адрес в проверки.
2. Новая проверка страницы — отдельным файлом `checks/product-<slug>.mjs`
   по образцу:
   - `checks/product-new.mjs` — универсальный цикл по нескольким страницам
     (данные против `data.js`, подпись, размеры, покупка, каркас, чужие
     остатки от шаблона);
   - `checks/product-men.mjs`, `checks/product-other.mjs` — проверка одной
     страницы для мужского и «другого» типа.

Существующие проверки чужих страниц (`product.mjs`, `product-men.mjs`,
`product-other.mjs`, `product-new.mjs`) не переписывать под новый товар:
они проверяют свои страницы. Исключение — общий список в `links.mjs`.

### Шаг 7. Проверить в браузере

Статика:

```powershell
cd C:\Sites\CozyPajamasStore
Get-ChildItem checks\*.mjs | Where-Object { $_.Name -notlike 'req-*' } | ForEach-Object {
  $out = node $_.FullName 2>&1 | Select-String -Pattern 'Проверок пройдено|НЕ ПРОШЛО'
  "$($_.Name) => $($out -join ' | ')"
}
```

Сервер (свой, без кэша, порт **8124**; порт 8000 занят сервером владельца —
его не трогать). Файл сервера — тоже в `$env:TEMP`:

```python
# $env:TEMP\cozy-serve.py
import functools, http.server, socketserver

ROOT = r'C:\Sites\CozyPajamasStore'


class Handler(http.server.SimpleHTTPRequestHandler):
    def end_headers(self):
        self.send_header('Cache-Control', 'no-store, must-revalidate')
        super().end_headers()

    def log_message(self, *args):
        pass


class Server(socketserver.ThreadingTCPServer):
    allow_reuse_address = True
    daemon_threads = True


with Server(('127.0.0.1', 8124), functools.partial(Handler, directory=ROOT)) as httpd:
    httpd.serve_forever()
```

```powershell
$srv = Start-Process python -ArgumentList "$env:TEMP\cozy-serve.py" -PassThru -WindowStyle Hidden
$srv.Id | Out-File -Encoding ascii $env:TEMP\cozy-8124.pid
Start-Sleep -Seconds 2
# … работа …
Stop-Process -Id $srv.Id -Force
```

Замеры — только через `~/.dsh/bin/browser.mjs`:

```powershell
$b = "$env:USERPROFILE\.dsh\bin\browser.mjs"
node $b --url http://127.0.0.1:8124/product-pages/solntse.html `
     --request C:\Sites\CozyPajamasStore\checks\req-product-new.mjs `
     --widths 375,768,1024,1280 --no-preflight --settle 2000
```

`checks/req-product-new.mjs` подходит любой пижамной странице: он меряет,
что фото загрузилось, размеры выбираются, без размера товар не добавляется
и показывается подсказка, с размером — кладётся в корзину с выбранным
размером, акцент свой, прокрутки вбок нет. Для подушки брать
`checks/req-product-other.mjs`.

Проверять ширины 375, 768, 1024, 1280 и 1440. Смотреть:
- фото загружено, `naturalWidth > 0`;
- название не вылезает, цена в одну строку, кнопки не обрезаны;
- `document.documentElement.scrollWidth === innerWidth` (нет прокрутки вбок);
- в консоли нет ошибок (`Runtime` слушает `browser.mjs`).

Модули по `file://` не работают — открывать только `http://127.0.0.1:8124`.

## 4. Грабли, проверенные на этом проекте

1. **Мужской шаблон и размеры.** В макете `M, XL, XXL, XXXL`. Если товар
   из секции `new`/`men` без своего поля `sizes`, набор — `S, M, XL, XXL`.
   Всегда сверять чипы с `getSizes(product)`.
2. **Широкий кадр давит колонку с кнопками.** В раскладке 1280px фото
   занимает свою ширину, сведения — остальное. При ширине кадра больше
   ~0.44 от высоты фото забирает слишком много: у «Нежного счастья»
   (576×1160) кнопкам оставалось 158px и подписи вылезали. Лечится общим
   правилом `grid-template-columns: auto minmax(220px, 1fr)` в
   `product.css` — оно уже есть, менять его не нужно.
3. **`data-size-error` — переключатель проверки размера.** Нет элемента —
   нет проверки: товар без размеров добавится без вопроса, и это правильно
   только для «других товаров».
4. **Цены.** В карточках каталога разряды разделяет неразрывный пробел
   (`formatPrice`), в разметке страницы — обычный. Не копировать
   из карточек.
5. **Остатки шаблона.** После замены искать в файле: название шаблона,
   `goods-women-03`/`goods-men-01`, `w03.png`/`m01.png`, старую цену,
   `XXXL`, слова из старого описания («махров», «велсофт»). Скрипт-копир
   с проверкой каждого образца надёжнее ручной правки: писать его в файл
   и запускать, а не править 360 строк руками.
6. **`data-section` и акцент.** Акцент задаёт вид товара, а не секция
   каталога. Менять `data-section` у существующей страницы нельзя — вместе
   с ним поменяются фон, кольцо и цвета.
7. **Общий CSS.** Любая правка `product.css` проверяется на всех девяти
   страницах до и после (замеры колонок, кнопок, прокрутки). Если меняется
   вид существующей страницы — согласовать с владельцем.
8. **Память.** `browser.mjs` отказывается стартовать ниже 3500 МБ
   свободных. Если памяти мало (Photoshop, браузер владельца) — сказать
   об этом прямо и не гонять сквозные проверки.
9. **PowerShell.** Inline `node -e` с кавычками ломается; `ReplaceFileW
   EIO` при записи — повторить операцию. Скрипты — в `$env:TEMP`.

## 5. Что считается готовой страницей

- файл страницы открывается по `http://127.0.0.1:8124/product-pages/…`;
- фото товара на месте, размеры фото в разметке — настоящие;
- подпись, название, цена, состав, описание и характеристики совпадают
  с `data.js`;
- чипы размеров совпадают с `getSizes(product)`; без выбранного размера
  «Добавить в корзину» показывает «Выберите размер» и ничего не кладёт
  в корзину; с выбранным — кладёт товар с этим размером;
- «Купить в один клик» ведёт на `../thanks-cart.html`;
- блок принта (если есть) работает: «Выбрать из каталога» ведёт
  на `../prints.html`, «Добавить свой макет» открывает выбор файла;
- карточка в каталоге на главной ведёт на новую страницу;
- прокрутки вбок нет на 375, 768, 1024, 1280, 1440;
- все статические проверки зелёные, новые — добавлены;
- README обновлён, коммит содержит только свои файлы.
