# AGENTS.md — всё, что нужно знать о проекте CozyPajamasStore

Один файл вместо прежних `docs/product-pages.md`, правил и заметок: здесь
и правила, и устройство, и проверки, и порядок работы. Читается целиком
перед первой правкой.

`README.md` — **витрина проекта** для людей: что за сайт, ключевые решения,
палитра, стек, ссылки на макет, живой сайт и репозиторий. Технического
описания в нём больше нет (старая подробная версия осталась в истории git):
всё, что нужно для работы, — в этом файле.

## 1. Что это за проект

Статический сайт магазина уютных пижам: **чистый HTML, CSS и ES-модули**.
Ни сборки, ни `node_modules`, ни препроцессоров, ни сторонних библиотек.
Сайт открывается как есть; картинки, стили и скрипты — обычными файлами.

- Адрес: `C:\Sites\CozyPajamasStore`
- Опубликован: `https://artem02031980.github.io/CozyPajamasStore/`
  (GitHub Pages; `.nojekyll` в корне, чтобы Jekyll не пересобирал папки).
- 145 страниц: главная, `prints.html`, две страницы благодарности
  (`thanks-cart.html`, `thanks-feedback.html`) и **141 страница товара**
  в `product-pages/`: «Новая коллекция» (6), женская (48), мужская (39),
  «Другие товары» (48).
- Порт для локальных замеров — **8124**. Порт 8000 занят сервером
  владельца, его трогать нельзя.

Состояние на 18.11.2026: рабочее дерево чистое, кроме
`assets/css/pages/prints.css` (правка владельца, не коммитить);
61+ коммит впереди `origin/main` — опубликованный сайт отстаёт,
пока владелец не решит пушить.

## 3. Как запустить и посмотреть

Модули по `file://` не грузятся (CORS) — только по `http://`.

```powershell
# сервер без кэша, свой порт 8124; файл сервера — в $env:TEMP
$srv = Start-Process python -ArgumentList "$env:TEMP\cozy-serve.py" -PassThru -WindowStyle Hidden
# … работа …
Stop-Process -Id $srv.Id -Force
```

`cozy-serve.py` — обычный `http.server` с `Cache-Control: no-store`,
корень `C:\Sites\CozyPajamasStore`, `ThreadingTCPServer`, `daemon_threads`.

## 4. Данные и логика

- **`assets/js/data.js`** — каталог: 141 товар (`id: 'goods-women-01'`…),
  поля: `id`, `section` (`new|women|men|other`), `title`, `subtitle`
  (состав), `types`, `ages`, `colors`, `price`, `image` (WebP), `alt`,
  `width`, `height`, `sizes`, `page`, `description`, `details`.
  Размеры картинок в данных обязаны совпадать с файлами.
- **`assets/js/prints.js`** — 17 принтов: `PRINT_PRICE = 500`,
  `PRINT_SIZE = 700`, `PRINTS`, `getPrint`, `printLabel`, `PRINT_AUTHOR`
  («Артём Мижорниев»; в каждом описании есть строка об авторе).
- **`storage.js`** — ключи localStorage: `cozy-pajamas:cart`,
  `cozy-pajamas:order`, `cozy-pajamas:message`, `cozy-pajamas:pages`.
  Всё чтение — через `parseJSON` (битые данные не ломают страницу).
- **`cart.js`** — только логика, без DOM: `addItem`, `setQty`,
  `changeQty`, `removeItem`, `getLines`, `getTotals`, `getProductsTotal`,
  `getFreePrints`, `getFreeServiceGap`, `lineKey`, `isPrintLine`.
  «Свой макет» — заявка, количество всегда 1 (и в `setQty` тоже).
- **Цена печати (правило владельца):** **один бесплатный принт за каждые
  15 000 ₽ товаров**. Два бесплатных — от 30 000, три — от 45 000.
  Принты и услуга «ПРИНТ» в сумму товаров **не входят** (иначе принт сам
  приближал бы порог). Бесплатные единицы раздаются по порядку позиций,
  у каждой позиции своя доля (`printLines` → `{free, paid, cost}`).
  В интерфейсе: «бесплатно 1 из 18», строка «Печать «ПРИНТ»», подсказка
  «до следующего осталось N ₽». Свой макет денег не добавляет.
- **`checkout.js`** — `validateField`, `validate`, `buildOrder`,
  `buildOneClickOrder`, `makeOrderNumber`, `submitOrder`, `initCheckout`,
  `initBuyNow`. Имя (≥2 букв) и телефон (≥10 цифр) обязательны, почта нет.
  Поля стоят **выше** кнопки «Оформить заказ»; при ошибке фокус уходит
  на первое неверное поле. Номер заказа: `ГГГГММДДччммсс-NNNN`
  (секунды и случайный хвост — чтобы два заказа подряд не совпали).
  `initCheckout()` вызывается на всех страницах с корзиной: главная,
  страница товара, `prints.html`. Переход после заказа —
  `pageUrl('thanks-cart.html')` из `utils.js` (путь считается от корня,
  иначе со страницы товара получался `product-pages/thanks-cart.html`).
- **`utils.js`** — `$`, `$$`, `delegate`, `debounce`, `formatPrice`
  (неразрывные пробелы!), `plural`, `uid`, `variantKey`, `lockScroll`,
  `unlockScroll`, `parseJSON`, `assetUrl` (картинки от корня проекта),
  `pageUrl` (страницы от корня), `escapeHtml` (данные пользователя
  в разметку — только через него).
- **`script.js`** — диспетчер по `data-page` на `<body>`: `home`,
  `product`, `prints`, `thanks-cart`, `thanks-feedback`. Новая страница
  без `data-page` получит набор главной.

## 5. Вёрстка: правила

- **BEM**: `блок__элемент--модификатор`. Никаких своих значений в разметке:
  цвета, отступы, типографика — токены из `assets/css/base/variables.css`.
- **Mobile-first**, точки перелома 767/768, 1023/1024, 1279/1280.
- **Комментарии — по-русски и по делу**: объясняют «почему так»,
  а не пересказывают код. Файлы начинаются с шапки: что это и зачем.
- **Разметка — копия образца.** Страница товара собирается из шаблона
  своего типа; шапка, корзина, принт, подвал и подписи совпадают
  с остальными страницами до класса.
- **Тексты и оформление — решение владельца.** Уже свёрстанные страницы
  и формулировки принимаются как есть: «улучшать» без просьбы нельзя.
- **Общий CSS меняется с замерами** до и после: колонки, кнопки,
  горизонтальная прокрутка на 375/768/1024/1280/1440. Если меняется вид
  существующей страницы — сначала спросить.

### Грабли проверок

- `formatPrice` ставит **неразрывные пробелы**: сравнивая текст в
  проверках, нормализуй `\u00A0` → пробел, иначе «8 500 ₽» не совпадёт.
- В шаблонных строках (код, который уезжает в браузер) `\s` превращается
  в `s`: регэкспы для страницы собирай без `\s` или экранируй `\\s`.
- `sweep.mjs` считает битыми только те картинки, что уже пытались
  загрузиться: ленивые ниже экрана — норма, а не поломка.
- Счётчик «Проверок пройдено» печатается в конце файла: новые проверки
  вставляй **до** блока «итог», иначе число отстаёт.
- `browser.mjs` подходит только для одной страницы за запуск; переход
  между страницами — отдельным файлом, как в `req-checkout.mjs`.

## 8. Как добавить страницу товара

1. Найти товар в `data.js` по названию. Если `page` уже заполнено —
   остановиться и спросить, что менять.
2. Выбрать шаблон по **виду товара** (не по секции каталога):
   женский — `klubnichnye-polya.html`, мужской — `myatnyy-vecher.html`,
   «другие товары» — `lyanyanoy-damask.html`.
3. Скопировать шаблон в `product-pages/<транслитерация>.html` скриптом
   (пути и кириллица — только файлом из `$env:TEMP`, не inline).
4. Заменить: `<title>`, `description`, фото (`src`, `alt`, `width`,
   `height` — настоящие размеры файла), подпись, название, цену, чипы
   размеров (`getSizes`), `id` у кнопок покупки, состав, описание,
   характеристики. После замены искать остатки шаблона: старое название,
   `goods-women-03`/`goods-men-01`, `w03.webp`/`m01.webp`, старую цену,
   `XXXL`, слова из старого описания.
5. Дописать в запись товара `page`, `description`, `details`.
6. Обновить `checks/links.mjs` (списки страниц) и, если товар встал
   в цепочку раздела, стрелки соседей; прогнать
   `node checks/product-arrows.mjs`. Добавить проверку страницы
   `checks/product-<slug>.mjs` по образцу своего типа.
7. Прогнать статические проверки и замеры на 375/768/1024/1280/1440.
8. Обновить `README.md` (таблица страниц товара) и этот файл, если
   изменились правила.
9. Коммит только своих файлов.

Типы страниц: женская — розовый акцент, есть размеры, блок принта и
строка состава; мужская — голубой акцент, свои размеры, блок принта;
«другие товары» — бежевый акцент, **без размеров и без блока принта**,
две колонки по центру. `data-section` задаёт фон, кольцо и цвета;
у него нельзя менять значение у готовой страницы.

Готово, когда: страница открывается по `http://`, фото на месте и
`naturalWidth > 0`, подпись/название/цена/состав/характеристики совпадают
с `data.js`, без размера товар не добавляется и показывает «Выберите
размер», с размером — кладётся в корзину с ним, «Купить в один клик»
ведёт на `../thanks-cart.html`, карточка на главной ведёт на страницу,
нет прокрутки вбок, статические проверки зелёные.

## 9. Правила работы агента

- **Чужое не трогать.** В рабочем дереве бывают незакоммиченные правки
  владельца (сейчас `assets/css/pages/prints.css`). Их не править,
  не форматировать, не добавлять в коммит. Если файл нужен для работы
  (например, `prints.html` при массовой вставке в шапку) — правку
  владельца упомянуть в отчёте.
- **Своё — своим коммитом.** `git add` только того, что менял сам;
  сообщение по-русски, 3–6 строк: что сделано, что проверено.
- **Ничего вне папки проекта.** Не создавать файлы и папки в `C:\Sites`
  и других местах: бэкапы, копии картинок и «страховки» — только
  в `$env:TEMP` и с уборкой в конце. Если бэкап нужен надолго — спросить
  владельца, где его держать.
- **Временные файлы — в `$env:TEMP`** и убирать за собой: серверы,
  скрипты конвертации, скриншоты, одноразовые `.mjs`. В проекте
  не должно остаться `.tmp-*`.
- **PowerShell и кавычки.** Inline `node -e` и `-replace` с кириллицей
  ломаются: любую массовую правку писать Python-скриптом в `$env:TEMP`
  и запускать `python файл.py`. После правки — `node --check` и прогон
  проверок.
- **Убивать только своё.** Сервер и Chrome — по PID; веерные
  `Get-Process … | Stop-Process` запрещены.
- **Ответы — по-русски и числами.** План на 2–3 строки до работы,
  отчёт на 3–5 строк после: что сделано, какие числа получились, какие
  файлы затронуты.
- **Не создавать новых `.md`-документов.** Всё знание — в этом файле
  и `README.md`. Появился новый раздел — правь их.

## 10. Что сознательно не сделано

Владелец проекта решил эти пункты **не делать** (аудит от 18.11.2026).
Не начинать без прямой просьбы:

- отправка заказов и вопросов на сервер — заказ пишется в `localStorage`,
  это учебный магазин; при запуске нужен канал (форма-сервис, Telegram);
- контраст кнопок ниже WCAG AA (белый на `#93b3d6` — 2.17, на `#cd74a2` —
  3.17). Тёмные варианты: `#4f739c` (4.92) и `#a3527f` (5.16);
- юридические документы (оферта, ПДн), реальные контакты в подвале
  (`mailto:`, `wa.me`, `t.me`, соцсети — заглушки), надпись «проект
  учебный» на страницах благодарности;
- SEO-пакет: `robots.txt`, `sitemap.xml`, `404.html`, `canonical`,
  JSON-LD, `og:*` на страницах товаров, абсолютный `og:image`;
- локальные шрифты вместо Google Fonts;
- сборка CSS в один файл и минификация JS (проект без сборки).

1. `node --check` для каждого изменённого `.js`.
2. Статические проверки (команда из §7) — 0 провалов.
3. `node checks/integrity.mjs` — 0 битых ссылок и якорей.
4. Если менялись страницы или общий CSS — замеры на 375/768/1024/1280/1440
   и `node checks/sweep.mjs http://127.0.0.1:8124 "" 320`.
5. Если менялись корзина, оформление или принты — сквозные из §7.
6. `git status`: в коммит идут только свои файлы, временных `.tmp-*` нет,
   сервер остановлен, файлы из `$env:TEMP` удалены.
