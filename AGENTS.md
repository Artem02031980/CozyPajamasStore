# Правила проекта CozyPajamasStore

Статический сайт магазина пижам: чистый HTML, CSS и ES-модули, без сборки,
без зависимостей и без `node_modules`. Владелец смотрит вёрстку в браузере,
страницы открываются по `http://` (модули по `file://` не грузятся).

## Что читать до работы

- **Страницы товаров** — `docs/product-pages.md` целиком, до первой правки.
  Там три типа страниц, пошаговый порядок, что менять в разметке и данных,
  как проверять и какие грабли уже проверены.
- **Остальное** — `README.md`: устройство секций, корзины, фильтров,
  принта, формы и всех проверок.

## Жёсткие правила

- **Чужое не трогать.** В рабочем дереве бывают незакоммиченные файлы
  владельца (сейчас это `assets/images/product-page/bg_men.png`,
  `bg_other.png` и `assets/images/products/other/Pillows/03.png`).
  Их не править, не форматировать, не добавлять в коммит.
- **Своё — своим коммитом.** `git add` только тех файлов, которые менял
  сам; сообщение по-русски, 3–6 строк: что сделано, что проверено.
- **Проект принимается как есть.** Уже свёрстанные страницы, тексты
  и оформление считаются согласованными. Переделывать их «для улучшения»
  без прямой просьбы нельзя.
- **Разметка — копия образца.** Новая страница товара собирается
  из шаблона своего типа, а не пишется заново: карточка, шапка, корзина,
  принт и подвал должны совпадать с остальными страницами до класса.
- **BEM и русские комментарии.** Классы — `блок__элемент--модификатор`;
  комментарии в разметке, CSS и JS — по-русски и по делу: объясняют
  «почему так», а не пересказывают код.
- **Mobile-first CSS**, точки перелома 767/768, 1023/1024, 1279/1280.
  Токены цвета, отступов и типографики — в `assets/css/base/variables.css`,
  свои значения в разметке не выдумывать.
- **Общий CSS меняется с замерами.** Правка `product.css`, `header.css`,
  `cart.css` и других общих файлов проверяется на всех страницах
  до и после: колонки, кнопки, прокрутка вбок. Если меняется вид
  существующей страницы — сначала спросить владельца.
- **Сервер свой.** Порт **8124** и только он: на 8000 работает сервер
  владельца. Поднимать с `-PassThru` и закрывать свой по PID.
  Файлы-серверы, скрипты и скриншоты — в `$env:TEMP`, за собой убирать.
- **Ответы — по-русски и числами.** План на 2–3 строки до работы,
  отчёт на 3–5 строк после: что сделано, какие числа получились, какие
  файлы затронуты.

## Проверки

Статические (быстрые, без браузера):

```powershell
cd C:\Sites\CozyPajamasStore
Get-ChildItem checks\*.mjs | Where-Object { $_.Name -notlike 'req-*' } | ForEach-Object {
  $out = node $_.FullName 2>&1 | Select-String -Pattern 'Проверок пройдено|НЕ ПРОШЛО'
  "$($_.Name) => $($out -join ' | ')"
}
```

Браузерные замеры — только через `~/.dsh/bin/browser.mjs`, по живому
серверу на 8124:

```powershell
$b = "$env:USERPROFILE\.dsh\bin\browser.mjs"
node $b --url http://127.0.0.1:8124/product-pages/solntse.html `
     --request C:\Sites\CozyPajamasStore\checks\req-product-new.mjs `
     --widths 375,768,1024,1280 --no-preflight --settle 2000
```

Правила замера: ширина задаётся протоколом (не `--window-size`), каждый
запуск с уникальным `--user-data-dir`, длинные страницы мерить числами,
а не скриншотом на всю высоту. Подробности — в глобальных инструкциях
агента.

Если свободной памяти меньше 3500 МБ, `browser.mjs` не запустится —
сказать об этом прямо и не гонять сквозные проверки.

## Чего в проекте нет

Сборки, `node_modules`, `scss/`, `dist/`, PHP, `api/`, сторонних библиотек,
автотестов на Playwright. Только ванильный JS и обычные `.mjs`-проверки
в `checks/`.
